- 人工用途许可独立保存在来源登记库，管理员提供证据与说明，24小时失效；不编造 robots 状态，不自动启用来源。原网页许可仍按原规则。身份/来源变化使许可失效并写既有 outbox。
- URL+来源确定文章身份；同名不同URL不合并。相同输入不增版本/不撤销原审核；变更需要现有文档 CAS，形成待审新修订。命令重放不重复计数，来源版本/政策版本与写入在同一批次复验。每天全站最多20个人工批次，不重置学生 Agent 额度。
- `document_discoveries` 保留同一原文的多个栏目/发现器出处；`manual_import_items` 仅为任务回执和CAS保护，不是另一套文章库。人工获取观察 status=0/intake_kind=manual，不冒充 HTTP 200；原发布时间与服务器获取时间分离。
- 原编辑/恢复入口同样检查来源和正文许可；0013在原子命令批次内绑定来源/政策版本，撤销与迟到写入竞态失败时全批次回滚。
- 新增匿名 `GET /api/public/content`，最多20条、offset最多200；每次读取原 fresh view，复验当前审批/修订、发布、生命周期、来源许可状态；只输出标题、原文链接、时间、来源、分类和自有简短说明，永不输出正文/私有内容。失效/旧version返回 NOT_FOUND，所有响应 no-store，复用现有边缘限流。

## 5. 真实批准→发布→匿名读取→撤回门槛

**负责人必须自行核对原文并在 Console 决定是否批准。** 测试代理只做只读检查，不替负责人做内容决定。

1. 负责人选择符合用途的记录，检查原文、分类和元数据许可；不为验收强行发布不合适文章。本次实际选定学工评审会通知。
2. 填写实际审核说明（至少两个字），点击批准；确认已批准后再发布。修改内容会使原批准失效，需重新核对。
