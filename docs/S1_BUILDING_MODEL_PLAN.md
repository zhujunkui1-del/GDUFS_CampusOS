# CampusOS 建筑 2.5D / 3D 自主建模方案

日期：2026-10-13。状态：**方案提交，未开始完整建模**。先完成 S1 地图范围、缩放与性能验收，再审核少量建筑试点。保持高德 JS API 2.0、MapAdapter、响应式 Web 和现有 Apple 式 UI。

## 1. OSM 资料覆盖率

已解析负责人提供的 map.osm 全部对象与 BBBike GeoPackage 全部图层。按关系13900183的两个校园分区筛选建筑；跨边界几何先审查，不把导出矩形当作学校范围。

| 指标                             | 当前数据       | 含义                                               |
| -------------------------------- | -------------- | -------------------------------------------------- |
| 校园内带建筑标签的轮廓           | 36个，全部闭合 | 含2个 building=bridge 连廊对象；不等于36栋独立建筑 |
| 有名称                           | 27/36，75%     | 名称、用途和改造现状仍需核对                       |
| 直接高度 height                  | 0/36，0%       | 不能生成声称真实的高度                             |
| 楼层 building:levels             | 4/36，约11.1%  | 2个教学楼主体、2个连廊；楼层不等于高度             |
| 独立建筑候选（排除上述连廊）     | 34个           | 仅2个有楼层信息，约5.9%；仍未有完整高度            |
| 已绑定现有地点且有建筑标签的轮廓 | 26个           | 与公开地点ID已有绑定基础                           |
| 对学校全部真实建筑的覆盖率       | 未知           | 缺校方完整清单，不能把34或36当真实总数             |

四个楼层标签均为5层，教学楼A/C的两个主体及两个连廊；缺层高与屋顶资料，不能自动乘一个假定层高得到“真实高度”。每个来源ID见 [资料审查JSON](research/s1/supplied-data-audit.json)，运行 python scripts/inspect-campus-sources.py 可复现。GeoPackage是EPSG:4326，与XML同属OSM，不能作为独立高度或外观证据。

## 2. 哪些可以用几何体绘制

| 建筑/设施            | 建议做法                                                  | 使用前提与缺项                                                               |
| -------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 宿舍楼               | 复用主体、窗带/走廊等参数化部件；每栋位置、足迹、朝向独立 | 已有12个编号地点；楼层、层高、屋顶与重复类型需核对，不把全部宿舍设成同一高度 |
| 教学楼               | 轮廓挤出 + 可复用连廊、楼梯与窗格                         | 命名不完整；A/C已映射不代表B–G全部已确认                                     |
| 实验楼               | 可复用规则主体，楼群组合分别建立                          | 缺完整名称、轮廓分属与尺寸；不以教学楼模板冒充外观                           |
| 超市/服务点          | 有独立轮廓才建体块，楼内服务绑定所属建筑与标签            | 12个生活服务对象不等于12栋独立建筑；点POI不能扩成建筑                        |
| 食堂/办公楼/交流中心 | 规则体量可程序绘制，特殊屋顶另处理                        | 名称、轮廓、用途及入口仍需核对                                               |
| 球场/泳池            | 保持平面地理几何与标注                                    | 类型或数量有冲突的继续待核验，不挤成建筑                                     |

**目前能直接复用的是有来源的二维足迹；真实高度挤出还需要资料。** 未知高度保持平面，不按“典型层高”自动补成真实楼高。若负责人以后接受风格化体块，另记近似表达规则与审核状态。

## 3. 哪些重要建筑需要照片与人工建模

优先试点为图书馆、体育馆、会堂；随后按资料质量选交流中心、代表性食堂或特殊办公楼。其屋顶、入口与连体结构可能决定辨识度，不能用通用长方体替代后宣称外观准确。

每个试点至少需要：主要方向的自有/获准照片、屋顶参考、足迹确认、楼层或实际高度、朝向与出入口。卫星图/鸟瞰图可核对关系，但可使用权与测量可靠性分别审查。

小红书可按负责人授权查找外观参考、登记原链接与作者；公开贴图或复用照片仍需许可。两张参考JPG尚未完成正式使用权审核。高德白模用于运行中的对照或回退，不提取内部网格、纹理或整库模型用于自主资产。

## 4. 高德原生楼块与 Three.js 协同

保留一个高德实例，按需加载 AMap.GLCustomLayer 自有建筑层，经 customCoords 对齐地图相机与局部坐标。共享GL上下文时不清空底图、正确恢复GL状态；不铺第二套独立相机地图。[高德官方 THREE 示例](https://developer.amap.com/demo/javascript-api-v2/example/selflayer/glcustom-layer)

一般建筑继续采用原生楼块；仅审核通过的少量建筑由自有模型替换。重叠范围使用官方楼块可见性机制，实测当前SDK支持后再确定局部隐藏方式；若不能可靠消除重叠，试点保持独立详情展示或退回原生楼块，避免两层闪烁。[高德楼块类型与样式接口](https://github.com/AMap-Web/amap-jsapi-types/blob/main/index.d.ts)

模型失败、GPU不足或效果未获认可时回退原生楼块。底图缺该建筑楼块时保留来源轮廓与标签，不承诺高德覆盖全部建筑。地图供应商与2D导航不随模型层改变。

## 5. 与搜索、导航、标注的数据绑定

建筑资源清单独立于地点事实和路线图，建议包含 building_id、place_ids、来源几何/坐标系、局部原点、朝向、尺寸来源、LOD资产URL、许可/地理审核状态、版本与更新时间。

- 保留 osm-way-* 稳定ID；一个建筑可有食堂/超市等多个服务地点，不按名称字符串连接。
- 模型点击产生相同 selectedPlaceId，复用详情、搜索聚焦和 FOCUS_PLACE/OPEN_PLACE_DETAILS 协议。
- 标签使用来源地点/入口锚点，随缩放展开、选中高亮；模型、标签和路线分别控制可见性与层级。
- 路线以已核验入口和路径为准；建筑中心、屋顶或照片位置不是导航终点，3D画面不能补成已通行隧道。
- 内部WGS84经官方服务转换为GCJ-02；局部米制坐标用地图公开接口转换，相机变换不反写地理事实。

## 6. 桌面/手机性能预算与降级

以下为**建议试点预算，不是实测结果**，底图成本也必须计入：

| 项目             | 桌面试点                | 普通手机试点             |
| ---------------- | ----------------------- | ------------------------ |
| 自有模型首屏下载 | ≤2MB压缩资源            | ≤800KB，优先轮廓/低细节  |
| 可见自有几何     | ≤100k三角形             | ≤30k三角形               |
| 自有层绘制调用   | ≤50                     | ≤20                      |
| 单地标GLB        | 目标≤500KB              | 目标≤200KB低细节资产     |
| 纹理             | 少量合图，优先≤1024边长 | 优先≤512，无纹理体块可用 |
| 显示目标         | 尽量60FPS               | 尽量30FPS，须实机测量    |

复用几何/材质与实例绘制，地标按可见范围加载，缓存有限，移除层时释放GPU资源。静态建筑不常驻额外动画循环，不逐帧触发React渲染；减少动态效果开关不替代性能降级。[Three.js渲染器接口](https://threejs.org/docs/pages/WebGLRenderer.html)

降级顺序：降低像素密度/纹理与LOD → 停用精细模型、回退原生楼块 → 2D轮廓与标签。上下文丢失、低内存/持续低帧率、加载失败均保持搜索/路线。iPhone/Safari、Android、热机/弱网、旋转缩放、AI抽屉和长时间浏览分别验收。

## 7. Blender 是否必要

**不是全校建模的必需工具。** 规则宿舍/教学楼可由代码生成参数化几何；Blender适合少量图书馆、体育馆、会堂等地标的屋顶、入口、UV、减面与LOD。先为一个资料完整的地标使用，再决定是否扩大人工建模。

建议交付可编辑 .blend 与运行用 .glb；复用部件时分别设置真实尺寸。Blender可导出glTF/GLB及实例扩展，加载端须验证支持。[Blender glTF说明](https://docs.blender.org/manual/en/5.1/addons/import_export/scene_gltf2.html)、[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)

**目前无需下载额外建模工具来修复范围。** 地图验收、试点资料齐全后若采用人工地标流程，再请负责人安装官方Blender。Three.js与解码器等依赖在试点决策后添加。

## 8. 实施顺序和回退门槛

1. 验收满屏、最小缩放、边缘拖动、旋转和横竖屏，保存真实截图与设备条件。
2. 负责人审核方案、选一个地标和一类可复用建筑，补充尺寸/照片/许可。
3. 只做这两个试点，验证位置、外观、入口、标签/路线遮挡和性能预算。
4. 合格后分批扩大；不合格保留原生楼块，未审核模型不进正式资源。

本方案没有添加Three.js依赖、创建完整建筑模型、公开未经许可图片或修改路线事实。

### 协同实现的兼容性门槛

高德官方THREE示例有历史版本差异。试点要先检测共享GL上下文与选定Three.js版本的兼容性，锁定版本后验证状态恢复；不能照抄旧示例就宣称兼容。Three.js不得独自修改SDK拥有的画布尺寸或主动丢失其上下文；优先通过LOD/纹理/实例复用降级，像素密度仅使用SDK允许的配置。
