## 3. 少量地标的照片与人工建模

优先候选为图书馆、体育馆、会堂；随后按资料质量选交流中心、代表性食堂或特殊办公楼。其屋顶和连体结构决定辨识度，不能用通用长方体代替后宣称外观准确。这些地标候选用于后续阶段。负责人本轮已选定南苑7栋，当前范围收紧为这一栋，先检视效果再讨论扩大。

每个试点需要：主要方向的自有/获准照片、屋顶参考、足迹与朝向确认、主体及屋顶的米制尺寸和高度依据。楼层数不能代替实际层高。模型若表现门、楼梯等细部，再补对应外观和尺寸；建筑周边到达的导航不以门的位置为前提。

卫星图、鸟瞰图可核对关系，可使用权与测量可靠性分别审查。小红书可按已有负责人授权查找外观参考并登记原链接与作者，公开贴图或复用照片仍需许可。原始参考 JPG/PNG 保留在文档包，不能直接转为公开纹理、瓦片或模型资产。

## 4. MapLibre / Three.js 渲染方案

主方案继续使用一个 MapLibre 实例和现有 MapAdapter。一般建筑以同版轮廓和可靠高度生成轻量体块；南苑7栋已通过 `CustomLayerInterface` 与 Three.js 共享地图 GL 上下文，将 WGS84 锚点转换为 `MercatorCoordinate`，使用米制比例和地图当前投影矩阵。模型层关闭自动清屏、恢复 GL 状态，不引入独立地图相机。参考：[MapLibre CustomLayer](https://maplibre.org/maplibre-gl-js/docs/API/interfaces/CustomLayerInterface/)。

南苑7栋试点使用锁定的 MapLibre 6.14.0/Three.js 0.186.1；共享上下文、投影和拾取已进入实际浏览器回归。渲染使用当前 `defaultProjectionData.mainMatrix`，静态模型不启动额外动画循环；依赖升级仍须重新验证。Three.js 不独自改变地图拥有的画布尺寸、不主动丢失其上下文；像素密度只通过地图允许的配置调整。不能照抄旧高德 THREE 示例后宣称兼容。

2D、挤出体块和精细模型共用本地外轮廓及地图版本。南苑7栋的原生体块与GLB已实现，GLB失败回退本栋2.5D体块并可重试；版本不兼容或弱设备回退二维轮廓。其余建筑没有可用楼块，继续保持平面。

高德白模和旧 `GLCustomLayer` 方案保留为历史比较候选。当前项目没有可切换的在线白模视图，不作为运行中的自动回退。未来若选用在线对照，应独立确认和验证，不能下载或转存其网格、纹理，也不能保证它与固定本地地图同版。

## 5. 模型、地点与导航的数据绑定

### 5.1 稳定 ID 与版本

建筑资源清单独立于地点事实和路线图，至少记录：

- `buildingId / footprintId / placeIds`：对应稳定的来源轮廓和地点 ID。
- `mapVersion / modelVersion`：地图与模型的兼容版本，旧模型不兼容时回退对应二维轮廓。
- 坐标系、局部原点、朝向、尺寸及高度来源、父子部件和重叠处理关系。
- LOD 资产 URL、内容哈希、许可/地理审核状态、更新时间。

覆盖 `osm-way-*`、`osm-relation-*` 及 `owner-*` 地物，不按名称字符串连接。节点地点可以关联模型，但没有独立轮廓的节点不能被挤出成单栋。一个建筑允许关联多个服务地点；复合体和子 way 的重叠先做部件归属核对，不把 41 个候选对象全部重复挤出。

| 当前对象     | 模型与交互绑定规则                                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 教学 E/F/G   | 子标签绑定 `osm-relation-4105730`；分界核验前使用父轮廓，不生成三套重复楼群                                                                                   |
| 实验 A—E     | 子标签绑定 `osm-relation-4105911`；标签位置不代表独立体量或入口                                                                                               |
| 水电冷充值点 | `owner-utilities-recharge` 绑定北苑 1 栋 `osm-way-313039013`；服务标签可独立选中，宿舍主体点击不被服务子点替代                                                |
| 八角楼       | `owner-bajiaolou` 关联行政楼 `osm-way-307437432`，按部件消解重叠，保留原始地物几何                                                                            |
| 语心桥       | `owner-bridge-e`、`owner-bridge-f`、`owner-bridge-g` 保留独立几何和路线连接；三个对象的 `labelPlaceId` 均为 `owner-bridge-f`，共用一个可见/可检索“语心桥”标签 |

模型点击沿用 `selectedPlaceId`、详情和 `FOCUS_PLACE / OPEN_PLACE_DETAILS` 协议。复合楼群按现有分栋逻辑选择最近的建筑标签并高亮父轮廓；服务子点不参与这种分栋分派。标签保留已经确认的地面锚点，不为了模型屋顶或视觉效果修改真实坐标。

### 5.2 坐标与图层

本地底图、地点、模型锚点直接使用 WGS84，局部米制转换通过地图公开接口完成。只有与高德在线服务交互时在边界转换 GCJ-02；已有路线服务数据在进入本地渲染前按现有接口转换，不能给本地模型统一加一次 GCJ-02 偏移。相机变换不反写地理事实。

现有建筑、体育、宿舍、服务复选框**只切换标签**，保留二维地物和未来模型。模型显隐由视角模式、资源审核、加载状态和性能降级控制，不能复用标签开关隐藏建筑。来源、许可和核验说明保留工程文档，产品不新增解释性小字。

### 5.3 继承当前导航规则

- 建筑起终点以周边候选位置求最短到达，不固定某扇门；建筑中心、屋顶、照片位置不能直接冒充道路终点。
- 教学/实验区域按已批准的简化地面策略可穿行，教学 A—G 连片通行；其他建筑和非桥水面仍为障碍。模型墙体不重新生成路由障碍，不改变已批准策略，也不生成室内楼层路线。
- 生活区与教学区之间的路线必经已确认的下沉隧道及两端连接。隧道批准来源是负责人确认和实际 OSM 连接，3D 外观不构成额外通行证据。
- 设备起点以独立虚直线引导到同区最近可接入步道或已批准教学/实验区域，之后走实线路网；引导线不登记为已核验道路，不跨普通水面或直接吸附地下边。
- 三座语心桥保留实际连接；教学 B→实验 C 沿当前最短路穿行并经语心桥，不能因模型选择或视觉遮挡重新南绕。
- 九门坐标只确认名称和标签位置，不自动启用校外连接或推断当前开放状态。

## 6. 视角、手机导航与交互约束

当前 `supports3D` 表示设备可使用倾斜视角，不代表建筑模型已就绪。建模阶段须区分设备能力、模型资源审核、加载成功和渲染可用状态；南苑7栋3D入口按本栋资产/版本和设备能力启用，加载失败保留2.5D并提供重试；不表示已实现全校3D。

模型接入沿用默认朝北 0°、最大倾角 38°、最大缩放 20，以及按视口、倾角和方位计算的动态缩放/覆盖约束。地图中心和地面视口保持在现有校园浏览范围及本地数据覆盖内，不另建自由漫游相机。

- 点击标签、搜索地点和文字选择起终点，统一使用现有 **600ms ease-out** 镜头，由快到慢，可被手势或新选择打断；减少动态偏好沿用即时切换。
- 地图上点选导航起终点保持镜头；规划成功后平滑拟合完整路线。模型点击也须遵循浏览、选点、导航三种交互状态。
- 聚焦和路线拟合按导航栏、详情、AI 抽屉等实际占位计算无遮挡区域；模型聚焦同时检查体量的投影范围，不能把屋顶偏移当作地点新坐标。
- 标签、路线、起终点和位置标记保持清楚，模型不能遮住导航信息；2D 回退保留相同地点与路线。
- 手机开始步行后保留上方方向/当前段距离、下方总路程/剩余估时/ETA、侧边定位/退出/方向/视角控件。搜索、图层、详情、主导航和 AI 继续隐藏，模型不新增无关窗口或说明段落。
- 退出/关闭导航清除路线、地下段、虚线引导、起终点和选择高亮，停止追踪并取消失效镜头回调。模型不得残留导航专用标记。
- 导航栏沿用非滚动外框、独立内部滚动区、固定标题/关闭按钮；模型接入后回归 Chrome/Edge 页面缩放、短窗口和滚动条条件，避免重现灰框。

## 7. 桌面/手机性能预算与降级

以下为**建议试点预算，不是实测结果**。本地底图成本须计入总加载与渲染成本，不能以模型单项预算替代整页验收。

| 项目             | 桌面试点                  | 普通手机试点              |
| ---------------- | ------------------------- | ------------------------- |
| 自有模型首屏下载 | ≤2MB 压缩资源             | ≤800KB，优先轮廓/低细节   |
| 可见自有几何     | ≤100k 三角形              | ≤30k 三角形               |
| 自有层绘制调用   | ≤50                       | ≤20                       |
| 单地标 GLB       | 目标 ≤500KB               | 目标 ≤200KB 低细节资产    |
| 纹理             | 少量合图，优先 ≤1024 边长 | 优先 ≤512，无纹理体块可用 |
| 显示目标         | 尽量 60FPS                | 尽量 30FPS，须实机测量    |

复用几何、材质与实例绘制，地标按可见范围加载，缓存有限，移除层时释放 GPU 资源。静态建筑不常驻额外动画循环、不逐帧触发 React 渲染；减少动态效果不替代性能降级。参考：[Three.js 渲染器接口](https://threejs.org/docs/pages/WebGLRenderer.html)，实现时以锁定版本验证。

拟定降级顺序：通过地图允许的配置降低像素密度、纹理及 LOD → 停用精细模型 → 有可靠高度且已验收时使用轻量楼块 → 二维轮廓与标签。当前南苑7栋使用桌面手机共用的第二版GLB，80384字节/4748三角面/7模型绘制/5材质/零纹理；第一版两档GLB保留为历史资源，2.5D原生挤出不变。像素密度降级仍为后续目标，不将高德白模作为自动回退。模型加载失败保留底图、搜索和路线；地图上下文丢失时保留业务状态，恢复地图后再恢复渲染，不宣称丢失期间仍能正常绘图。

验收包括 iPhone/Safari、Android 实机、热机/弱网、连续旋转缩放、AI 抽屉、导航和长时间浏览。桌面浏览器手机视口、受控 GPS、截图和既有 E2E 不能证明手机模型 FPS 或现场定位达标。

## 8. Blender 与交付资产

**Blender 不是全校建模的必需工具。** 规则宿舍和教学楼可采用参数化几何；少量图书馆、体育馆、会堂等地标的屋顶、UV、减面及 LOD 可采用 Blender。先选资料完整的试点，再按人工建模流程确定工具和依赖版本。

人工模型建议交付可编辑 `.blend` 与运行用 `.glb`；程序模型保留参数、生成代码和尺寸来源。每个资产附对应轮廓/地点映射、版本、LOD、来源许可和审核记录。Blender 导出及加载端扩展支持须在试点中验证。参考：[Blender glTF 说明](https://docs.blender.org/manual/en/5.1/addons/import_export/scene_gltf2.html)、[Three.js GLTFLoader](https://threejs.org/docs/pages/GLTFLoader.html)。

原始资料保留文档包；通过来源、许可和地理审核的运行资产才放入 `public/`，隔离测试夹具留在 `tests/`。已按单栋试点需要加入Three.js及其加载/导出器，未安装Blender或额外解码器。当前3D可编辑源为 `scripts/build-nanyuan7-v2.mjs` 和 `docs/model-previews/nanyuan7-v2/design.json`，负责人批准与高度依据在 `owner-model-review.json`；通过 `scripts/publish-nanyuan7-v2.mjs` 显式验证/发布，运行资产与哈希在 `nanyuan7-model.json`，不在启动/构建时重建模型。第一版生成器/清单保留历史，其生成器阻止覆盖已批准的第二版。

## 12. 宿舍标准模板与批量性能门槛（2026-10-15，负责人视觉验收后）

当前交互取代前述菜单：默认2D，一个按钮直接循环2D→2.5D→3D→2D，浏览/导航文字#1d1d1f，镜头仍600ms。南苑7栋GLB、原生2.5D、材质与灯光参数冻结；正式地图只增加静态阴影缓存，首次加载/透明度变化/GL恢复时更新，不新增灯光或改变外观。

宿舍标准模板记录在dormitory-template.json，范围为南苑、北苑、师苑、友苑。可复用柱梁、阳台/廊道、栏杆、窗面、材质与生成规则；长度、宽度、层数/高度、屋顶、外立面、真实足迹和中庭独立调整。21米/7层只属于南苑7栋，其他栋需要真实来源或负责人确认。不同类型不能直接整栋比例拉伸后冒充准确新楼。

### 实测结果与适用范围

独立tests/performance/dormitory-stress通过loopback3013运行，复制场景坐标在虚拟[0,0]，仅TEST标注，无正式placeId/导航数据，不覆盖校园地点。Edge149、RTX4070 Laptop、Ryzen7745HX，桌面1440×900/DPR1与手机视口390×844/DPR3。主矩阵48轮，另有策略/近景/真实指针/正式地图诊断，详情及完整指标：[性能对比报告](performance/dormitory-2026-10-15/REPORT.md)。

同模板60栋全景：模型含阴影调用约694→43，桌面CPU提交2.19→0.14ms，帧间隔P956.8→4.7ms；固有三角面仍284880。单栋正式模型稳态调用13→8。页JS就绪内存桌面约9.37→7.88MiB，但不能作为GPU/整进程内存。批处理首次矩阵/包络构建约32–38ms，静态性能改善不等于加载无峰值。当前手机视口仍用RTX4070，不能宣称普通手机30FPS已达标。

### 优化采用和后续门槛

- 基础：已实现共享几何/材质的跨建筑InstancedMesh模块，10栋为一组，测试已验证资源所有权和原模板边界。正式多栋接入前补齐每实例placeId拾取、独立高亮与透明度语义，避免共享材质误选全组。
- 剔除：默认对象包络剔除已启用。细分格网可减少近景提交三角面，但全景调用169高于43；按设备GPU压力选择组尺寸，不统一最细分组。
- LOD：隔离adaptive探查验证远景原2.5D体块/近景原GLB，正式应用仍保留已验收南苑7栋设计。阈值及近景首次加载峰值后续验收。
- 加载：同一GLB网络只一次，不代表真实不同楼型下载量。分帧构建探查会摊开主线程工作，但手机视口就绪261ms高于常规165.9ms；单栋不强行分批。实际多文件按视野/优先级增量加载，并预备可见模型。
- 下一批建议3栋：南苑8、南苑9、北苑1，先核对层数/高度/屋顶/立面，并回归充值点父子选择；随后师苑/友苑各选资料完整对象检验不同类型。初期细节同屏建议≤10栋，扩大前以真实差异模型与手机实机/热机/弱网回归确认。

正式校园仍只有南苑7栋立体模型。60个相同复制体只证明本机隔离规模，不能直接批准全校批量制作。最终呈现FPS、GPU VRAM、整页GPU耗时及进程完整RAM未可靠归因，详细口径以报告为准；资料和实机依赖继续登记BLOCKERS。
