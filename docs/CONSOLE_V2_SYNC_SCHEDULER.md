# 官网采集调度（D-067，2026-10-23）

## 目标架构

- Cloudflare Preview Worker 是官网任务主执行器；`scheduled()` 每分钟登记到期任务并推进云端任务。
- 本地 `scripts/console-sync-runner.mjs --run --watch` 是协作执行器。云端与本地共用 D1 `ingestion_jobs`、来源规则、租约、fence、许可复验和文章 URL 幂等。同一时刻同一来源只有一个有效租约；空闲执行器可以领取队列任务。
- 官网文章不在普通页面请求中抓取。云端使用现有 Preview Worker，不增加 Queue、Worker、R2 或付费资源。
- 公众号采集保持本地；除负责人今后主动提出外，不评估迁云。

## 官网采集模块

后台 `/admin/web-collection` 集中管理唯一的官网采集间隔、自动采集暂停、多个栏目入口、文章路径、解析选择器、访问许可和云端/本地执行状态。总览与信息源详情不再放官网执行器、日预算、官网周期和任务列表；页面不展示最近任务列表或执行器授权区。

全部官网共用1、3、6、12或24小时的统一间隔，默认24小时；不提供单站周期覆盖。`knowledge_sources.web_profile_json` 保存多条栏目入口、文章路径前缀、标题/日期/正文选择器及同站请求节流间隔。请求节流用于尊重站点负载和robots Crawl-delay，不代表采集周期。规则修改会递增来源版本并使旧访问许可失效，需管理员按新规则复核。栏目与解析配置从官网行内的“配置入口”打开。

配置入口会逐条检查同一 HTTPS 主机。任务按多栏目入口与分页检查，列表页每次提交一批链接，检查点记录已访问分页的摘要，允许后续继续扫描。首页只作为发现线索，不自动当作已核验的文章列表。

## 执行与容量

迁移0030移除 CampusOS 原先20次网络预留/日、10个官网任务/日和18次请求的全站守卫。到期任务每次按页批量登记，Worker后续tick继续处理；总任务不再受 CampusOS 固定日上限限制。单次批量是分页调度，不是日总量上限。

全局暂停、来源停运、D1租约/fence、当前来源/规则版本和有效许可仍会在写入时复验。403、429、robots拒绝、登录要求、重定向或网络失败会停止该请求并记录状态，不换身份绕过。应用内全局日预算已移除；Cloudflare套餐的CPU、每日请求、D1 Rows read/write及源站容量仍是实际运行条件。

各来源按规则设置同站请求节流间隔，默认1秒；若robots声明更长的 Crawl-delay，则遵守较长值。本地执行器继续固定公开IP并拒绝私网地址；Worker使用 Preview 的 `global_fetch_strictly_public`，并只访问来源配置中同源HTTPS链接。
