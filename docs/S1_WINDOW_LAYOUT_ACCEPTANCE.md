# S1 浏览器缩放与短窗口检查（2026-10-14）

## 用户补充的触发条件

Chrome/Edge 最大化且页面缩放大于100%，或普通窗口高度不足时，操作导航栏可能出现灰框；调整尺寸、降低缩放或关闭导航栏会消失。不是“规划步行路线”按钮单独触发。原图仍作为内部反馈保留。

## 已复现并修正的布局问题

1. 基线提交7e126c2，Chrome 最大化300%：视口高310px，页面滚动高度320px。地图页继承的最低高度造成外层滚动，画布宽度还会受到外层滚动条影响。地图页单独取消最低高度，主容器用overflow:clip；其他页面保持自己的滚动。
2. 修正外层布局后、修正镜头前，普通窗口1000×550：路线起点底部426px，导航栏顶部192.65px，起点落在底栏下方。CSS在宽度不大于1024且高度不大于500的视口采用底栏，而镜头此前只按宽度760判断。现按面板实际左右边界识别占位，兼容详情抽屉。
3. 低矮窗口规划时隐藏手机主导航及AI浮钮，把导航栏停靠底部8px，限制其高度并保留内部滚动；路线在剩余可见区域中拟合。

4. 每次规划前恢复2.5D进一步检查，普通窗口1000×450：2D路线端点底部154px，底栏顶部148.65px。独立投影副本继承了主地图当前倾角的约束，最终缩放被过高的下限钳住。副本现使用目标倾角，实际动画仍按当前/目标倾角保留边界约束；同一10秒复现由失败转为通过，保持一次平滑过渡。
5. 低矮窗口贴底后版权署名曾被面板覆盖，实际命中检查失败；署名置于面板前，面板底部预留空间，链接可见可点。

上述滚动、占位误判、最终视角与署名问题均在修改前得到实际失败断言；不将它们等同于已经复现用户原灰框。

## 实际浏览器检查

使用安装的Chrome/Edge、有窗口模式、临时独立配置目录；通过浏览器设置改变原生页面缩放，通过窗口接口最大化/改变普通窗口尺寸。不是CSS zoom或仅设置模拟视口。系统显示DPR为1.5；150%页面缩放对应DPR2.25。版本与实际视口记录在measurements.json。

每款浏览器15组配置：最大化100%、110%、125%、150%、175%、200%、250%、300%；普通窗口宽1000、高800/650/550/500/450/400且100%；普通窗口1000×650且150%。分别执行起终点输入、建议选择、规划、重置与面板滚动，再检查关闭导航清除路线。

每次重规划先恢复2.5D，分别截图/检查输入选择后的2.5D视角与规划后的2D路线；检查视口四角仍在本地覆盖范围内。图形设备为实际NVIDIA RTX4070 Laptop/D3D11，记录在JSON，不是软件渲染替代。

断言检查：

- 页面滚动高度与视口一致，画布CSS与物理缓冲尺寸匹配实际DPR。
- 用仅在测试中设置的洋红色画布背景暴露未绘制区域，避免正常底色相同掩盖空洞；同时扫描原#ECF0EF连续色块。
- 两端路线标记在视口内，底栏布局时位于面板上方；没有“Map cannot fit within canvas”警告。
- 关闭导航面板后无路线端点；最终截图已移除诊断背景。
- 版权链接在最上层可点击，WebGL上下文未丢失。

生产Workers入口：http://127.0.0.1:3000/map。Chrome/Edge原生矩阵各1项通过，15组配置中洋红及原灰色最长连续行均为0。测试脚本默认跳过，显式启用时只运行桌面项目；不改变用户常用浏览器配置、不采集个人GPS。
