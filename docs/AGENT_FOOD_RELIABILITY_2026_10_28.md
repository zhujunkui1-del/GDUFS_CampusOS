# 校园美食检索、真实外搜与输出协议修复（2026-10-28）

## 实际复现

使用两个原句“有什么好吃的吗”“广外大学城校区有几个食堂，第一食堂有什么好吃的”，原Preview均只执行内部知识检索，未执行外搜。候选实际为LSE留学经历、生活主题书展、新书速递：一篇提到LSE食堂不好吃，另有书名《这本书很好吃》，被粗粒度口味规则当作可回答的校园美食证据。第二问真实输出包含模拟tool_call文本，但并没有执行所写外部查询。before.json保留候选、工具轨迹和输出标记。

## 实现

- 查询先保留校区与餐厅实体；不带地点的美食泛问使用当前CampusOS大学城地图语境，不假称已取得用户GPS。显式北校、一饭、素食、不辣等条件保留。公开外搜使用简短校园/场所关键词，仍排除手机号、学号、密钥等私密字段。
- FTS增加食堂、饭堂、餐厅、社团等主题扩展，继续已有索引、96片段/32文档候选边界；在排序/返回前校验标题、正文片段与本次用途。不让留学食堂、图书口味比喻、考点与充值操作指南替代广外食堂推荐；用户明确查询考试/支付用途时相关材料仍可检索。不是删除原文章或改13类taxonomy。
- 内部缺少相关体验资料时，通过原有Skill Registry自动执行外部搜索；口味体验可用小红书，学校规则/时限仍优先官方。没有新增按次人工授权或来源审核。真实请求经既有工具权限、参数、超时与预算检查，origin=server_plan与模型自主调用区分。
- planning与answer阶段共享事实规则，但最终阶段不再带“必须调用工具”的义务；最终tools为空时，只综合已经执行的结果。服务端先缓冲并检查输出，文本模拟调用不被解析成可执行命令。首次异常最多同证据纠正一次，仍异常则不给用户显示代码。不增加无界重试，不重取小红书数据。
- 历史伪调用在显示与模型历史中转为正常错误说明；不篡改存储记录。历史及当前来源卡片按原问题主题过滤，引用保留原位置编号，避免删卡后错指链接。原折叠来源、蓝色上标链接与页面布局保持。
- 普通餐饮查询已取到可用正文、但模型生成失败时，直接给带日期/出处的原文短摘录，不额外调用模型或丢弃检索结果。metrics保留answerMode=evidence_excerpt与真实modelFailureCode，不把模型失败记作生成成功。取消、无正文、标题元数据、正式政策或特殊医疗饮食问题不借此编造菜单答案。
- 实测曾出现“本鱼摸鱼逛遍南校食堂”，已转为失败回归并加入正向亲历检查。最终输出不许以人格假造现场经历或校园排名；社团发现不擅自加校方官方认证。真正原文引文与助理自述分开处理。
