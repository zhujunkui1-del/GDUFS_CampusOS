# 离线阈值实验报告：reference 门槛降到 4 的效果

日期：2026-11-08
范围：**只读**，未改动任何生产代码。脚本位于 `.tmp/exp/`。

## 一、实验方法

1. `.tmp/export-corpus.mjs` 从 D1 导出全量语料 **3295 篇**（`.tmp/corpus.json`，字段 id/title/body/body_format/body_status/published_at/url/source_id）。
2. `.tmp/exp/threshold.mjs` 用 esbuild `onLoad` 插件在打包时**改写 `src/lib/ingestion/article-intent.ts` 里的三个阈值字面量**，再调用真实 `classifyArticleContent()` 跑全量语料。生产代码零改动。
3. 基线复现：`{"knowledge":37,"radar":1821,"unknown":1437}`，与 D1 完全一致，说明实验口径可信。

## 二、结论：阈值不是瓶颈

| 变体 | reference | timely | mixed | knowledge | radar | unknown |
|---|---|---|---|---|---|---|
| baseline | ≥6 | ≥5 | ≥6 | **37** | **1821** | **1437** |
| ref≥5 | ≥5 | ≥5 | ≥6 | 37 | 1821 | 1437 |
| ref≥4 | ≥4 | ≥5 | ≥6 | **37** | **1821** | **1437** |
| ref≥3 | ≥3 | ≥5 | ≥6 | 42 | 1821 | 1432 |
| ref≥4 + mixed≥4 | ≥4 | ≥5 | ≥4 | 35 | 1821 | 1439 |
| ref≥4 + mixed≥3 | ≥4 | ≥5 | ≥3 | 37 | 1819 | 1439 |

**把 reference 门槛从 6 降到 4，knowledge 依然是 37 篇，一篇都没变。** 降到 3 才多出 5 篇。

## 三、为什么无效：分数分布是极度离散的

把每篇文章的 `reference` / `timely` 实际分数打出来后（`.tmp/exp/scores.mjs`）：

```
reference 分布（按 destination）
radar     0:1797  3:2  6:2  7:5  8:3  9:3  10:6  11:2  13:1
unknown   0:1423  3:8  7:2  8:4
knowledge        7:9  8:8  9:7  11:1  12:4  13:3  14:3  15:1  19:1
```

**unknown(1437) 里 reference=0 的有 1423 篇（99.0%），reference=3 的只有 8 篇，reference=4~6 的一篇都没有。**

也就是说根本不存在「差一点就够」的候选池。门槛设在 4、5、6 是同一个效果，因为没有任何文章落在这一区间。

## four、真正的分布形态

unknown(1437) 的构成：

|类型|篇数|占比|
|---|---|---|
|reference=0 且 timely=0（纯新闻稿，无任何信号）|**1164**|81.0%|
|reference=0，timely>0（有短时效信号）|259|18.0%|
|reference>0，timely=0|9|0.6%|
|reference>0，timely>0|5|0.3%|

timely 分布：`0:1173  2:109  4:69  5:54  6:29  8:1  9:1  11:1`

所以问题的真相是：**信号根本没触发**，而不是「触发了但分数不够」。

## five、根子在权重表覆盖面

`article-intent.ts` 的 reference 侧单个加分项：

- policy +6（唯一的单项达标项）
- experience +7
- serviceDirectory +4
- procedure && referencePurpose +4
- guide +3
- norms && referencePurpose +3
- serviceOperations +3
- bodyReference && procedure +3
- referenceSection +3

timely 侧却有四个单项达标项：leadTask +8、reportPurpose +8、report +6、datedCall +6。

**「招生简章」「实施细则」「培养方案」「工作方案」这类高校最常见的长时效文档，在 referenceScoreSignals 里一个词都没有。**它们只能靠 `guide`(+3) 或 `procedure`(+4) 蹭分，凑不到 6。

## six、有效的杠杆（已实测）

### 杠杆 A：标题长时效词加权（推荐）

```js
if (/(?:招生简章|实施细则|管理办法|培养方案|工作方案|考核细则|招生方案|管理规定)/.test(text.title)) reference += 6;
```

结果：**knowledge 37 → 52（+15）**，radar 1818，unknown 1425。

新增的 15 篇全部是真正的长时效文档，零误伤：

- 《古典文学与文化微专业招生方案》
- 《研究生教学管理实施细则（广外校〔2026〕19号）》
- 《新闻与传播学院"智能传播"微专业招生工作方案》
- 《经济贸易学院推荐2027届优秀应届本科毕业生免试攻读硕士学位研究生工作方案》
- 《会计学院推荐2027届优秀应届本科毕业生免试攻读硕士学位研究生工作方案》
- 《出口管制与跨境经济制裁合规风控高级研修班招生简章》
- 《2026"未来领航者"英语探索夏令营招生简章》
- 《广外雅思2026暑假招生简章》
- 《广外・夏日成长暑托班招生简章》
- …（共15条）

### 杠杆 B：更宽的关键词表（噪声上升）

```js
if (/(?:办法|细则|章程|条例|规定|简章|方案|规程|制度|手册|指南|须知)/.test(text.title)) reference += 6;
```

结果：knowledge **37 → 73（+36）**，radar 1815，unknown 1407。

但加了噪声：《中央纪委国家监委公开通报八起违反中央八项规定精神典型问题》《论公益诉讼管辖制度的重构》《与谈人发言｜人工智能立法的基础理论与制度建构》《主旨发言｜丁晓东》——这些是讲话稿/通报，不是参考文档。

**结论：用窄词表（杠杆 A）更稳。**

### seven、灰区兜底：把纯新闻稿归入雷达

```js
if (destination === "unknown" && text.bodyAvailable) { destination = "radar"; radarCategory = "campus_notice"; }
```

结果：radar **1821 → 3073**，unknown **1437 → 185**。

这正好解释了用户看到的「雷达3000+」：那1437条灰区本来就是按雷达逻辑展示的（`public-content.ts:128`），现在只是把它们正式归位到 radar。语义上是正确的——它们确实是新闻稿。

### eight、无效的杠杆

|尝试|结果|
|---|---|
|去掉「radar无分类即降级」兜底|unknown −54，radar +54，杯水车薪|
|mixed分支改 policy/guide 优先|knowledge **−4**（37→33），方向错误|
|把 mixedFloor 从6降到4或3|knowledge −2 / −2|

## nine、建议

按性价比排序：

1. **加窄词表标题加权（杠杆A）**：knowledge +15，零误伤，改动最小。
2. **加灰区兜底（杠杆 seven）**：unknown −1252，雷达语义归一。
3. **不动阈值**：reference≥4 / ≥5 / ≥6 三者等价，改了没用。
4. **不动 mixedFloor**：降低反而减少 knowledge。
