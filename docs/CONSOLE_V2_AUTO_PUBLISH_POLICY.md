# Console V2 自动发布政策

默认没有任何来源自动发布授权，不把4个旧enabled或3篇历史人工批准推断为系统授权。管理员预先批准来源级用途、有效期、规则版本和默认正式分类后，固定系统主体才可发布。采集器/模型不能传approved/admin或构造系统身份。真实三篇已撤回内容保留撤回保护，不因升级或作者变更自行复活。

确定性标题/许可内文本分类、简短标题说明、显式时间证据先于发布。普通公告/政策不要求活动时间；讲座等原文应有时间的内容缺证据入审；日期精度不填时刻，相对时间无锚点unknown。许可不满足直接阻断，未知但可补录的必需字段入异常队列。正文抓取失败与可发布metadata-only区分。

通过检查绑定当前内容修订/hash、业务版本、来源和政策版本；原子受限自动发布写原版本/审计/outbox。源更新覆盖此前人工修正但保留字段差异/旧版本；304/失败/未变输入不能覆盖可靠人工内容。取消/改期或无法确认的新版本撤销旧公开门禁，并使关联事件待核、索引失效。未开发雷达或RAG，不能宣称已有这些前端消费者。

统计按真实处理记录计算，隔离夹具和真实来源分开；真实授权/运行分母0时N/A，不给虚构自动发布率。

## V2-B 实现边界（2026-10-18）

0015建立固定系统主体、来源级授权、当前修订原文证明、完整性检查、自动发布审计及按修订复用的大对象快照。默认政策不存在即阻断。人工导入需管理员核对原文一次；受控官网成功抓取证据按当前修订匹配，可走自动检查。元数据摘要为明确指向原文的标题说明，不冒充阅读全文后的摘要。日期未知的显式策略只适用于元数据；活动关键事实继续要求核验。

自动处理复用原Console命令、CAS、发布触发器、版本和outbox。既有撤回内容初始化保护。来源更新通过原增量提交生成修订、撤销旧公开状态，关联事件重新待审；失败/304处理沿用原保护。未开发多来源重大事实矛盾智能识别，现有关键字段冲突转人工。现阶段不宣称正常文章全部自动发布。

## 最终门禁

1. 来源当前已启用，有广外关联、运营证据和有效访问/用途许可。
2. human admin明确授权源级发布范围、正式分类、未知日期策略与有效期（1–30日），不默认给220源授权。
3. 当前修订必须来自受控官网成功抓取，或由human admin在原子导入/核对命令中确认原文。人工作出的修改不能继承旧HTTP/304证明；operator和采集器不能自称核验完成。
4. 检查绑定内容修订/hash、业务版本、源/政策版本、控制代次及规则版本。时间/地点重要事实不因source verified而自动变成timeVerified/placeVerified。
5. 元数据发布不要求正文；已许可摘录最多500字符，许可全文最多50000字符。无许可只生成明确指向原文的标题说明；有许可可用简短原文摘录。正文与附件完整性不混同。无证据的日期保持null，不补今天或日界时刻。
6. 普通通知/政策不要求活动时间。活动举办/报名截止分别解析；缺关键事实或取消/改期冲突进入异常。未知地点不猜测大学城地点。当前不是完整中文语义分类器或校园雷达，需真实语料持续评估。
7. 人工拒绝/退回阻止自动重试发布；源新修订使用新原文为事实基线，但此前人类否决需明确批准解除。人工撤回独立保护，白名单/政策续期不自动解除。
8. 原作者真正变化才生成新修订并覆盖旧人工事实修正，保留旧载荷、版本和差异；304/同指纹不覆盖。关联事件先转待核，outbox失效。当前没有日历/雷达/Agent知识索引消费者，不宣称已经完成这些后续模块。

系统publisher只能提交受门禁约束的发布命令；不能新增来源、批准源政策、登录Console或读取学生会话。所有发布使用既有命令、审核状态、CAS、审计、outbox。

独立SQLite端到端同类组：8篇经来源级许可的隔离夹具，6篇普通通知真实经过D1写入和系统发布，2篇活动缺时间证据进入异常；自动发布率75%，异常入审率25%，阻断0/8。不是线上采集文章，也不代表真实校园语料准确率。真实preview没有任何自动发布源级授权，真实自动发布分母0，率为N/A。未为了测试公开虚假文章或未经批准的正文。

## 人工决定简化（负责人2026-10-18修订）

来源启停由管理员直接决定，不再要求另填关联/运营说明；自动执行仍按实际访问/版权/来源级政策及确定性检查运行，启用不等于授予全文权利。人工批准/退回/拒绝不需要理由，按钮提交后由服务端记录“管理员批准／退回／拒绝”。人工决策与机器自动发布为不同动作；人工拒绝/撤回不会被自动重试撤销。审批API仍限制admin/reviewer，并保留CAS、版本与审计。
