## 技术核验与待确认事项

### D-008：Next.js 部署适配器

- 核验结果（2026-10-12）：Cloudflare 官方仍提供 Next.js on Workers 的 OpenNext 指引；当前文档同时推荐 `vinext` 作为新的 Next.js-on-Workers 项目的默认方案。
- 影响：基线指定 Next.js + Workers，但未锁定 OpenNext 或 vinext。两者的兼容范围、迁移风险、开发体验和比赛交付风险需要在 S0 做小型适配验证。
- 决策：负责人于 2026-10-12 确认启动 S0；保留 Next.js + TypeScript + Workers 的基线并验证 OpenNext，不切换至 vinext。最终版本组合和实际运行证据见下方 S0 记录。
- 来源：[Cloudflare Next.js 文档](https://developers.cloudflare.com/workers/framework-guides/web-apps/nextjs/)、[Cloudflare Web Apps 文档](https://developers.cloudflare.com/workers/framework-guides/web-apps/)。

### D-009：Cloudflare 数据与部署服务

- 核验结果：D1 使用 SQLite 语义并支持 FTS5；Vectorize 当前为 GA，可连接 Workers 与 Embedding 模型；R2 可绑定到 Worker。Vectorize 建索引前需确定 embedding 维度/距离度量。Workers 各套餐限制不同。
- 影响：这组组件技术上可作为候选，但选用前须定模型/维度、数据隔离、成本/配额、部署区域与备份。负责人已指定域名 `gdufs.ccwu.cc`；账号、套餐和 DNS/HTTPS 接入仍未核实。
- 决策：保留设计文档推荐方向；不创建线上资源、不产生费用，直至负责人确认。
- 来源：[D1](https://developers.cloudflare.com/d1/)、[Vectorize](https://developers.cloudflare.com/vectorize/)、[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)。

### D-010：高德 SDK、路线和坐标

- 核验结果：高德 JS API 2.0 支持地图交互、倾斜/3D 相关功能和步行规划；高德官方路线服务也提供步行路线 API。JS API 需要 Web JS API Key 与安全密钥，生产建议用服务器代理；高德底图采用 GCJ-02。
- 关键限制：SDK/API 能调用，不代表广外校内每条道路、建筑入口或南校地下隧道有真实拓扑覆盖。不能仅凭外部步行规划的结果宣称校园路线已核验。S1 路线成功状态必须基于有来源、许可和核验标记的路段。
- 决策：高德仍为第一候选，不把 AMap 响应直接持久化为可再分发 POI/路网数据库；内部坐标约定、转换与路线数据授权需在 S1 前确认。
- 来源：[JS API 2.0 文档](https://lbs.amap.com/api/javascript-api-v2/documentation)、[JS API 安全密钥](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode)、[步行路线 Web 服务](https://lbs.amap.com/api/webservice/guide/api/newroute)、[坐标说明](https://lbs.amap.com/api/javascript-api-v2/guide/abc/basetype)。

## D-099｜final 阶段误拒与过宽漏召回否定修复（2026-10-29）

`学校哪里可以锻炼身体` 在检索正确、证据充分的情况下仍输出原文摘录，指标为 `MODEL_SERVICE_UNAVAILABLE`、`groundingChecks=0`。`wrangler tail` 的 `FINAL_REJECTED` 显示实际触发者是 `falseNegativeAnswer`：其首条规则在答案没有 `[来源 n]` 时，把任意“没有/未查到”当作“否定相关文章存在”，于是“没有查到具体开放时间”这样的合理缺口被连续拒绝两次，最终降级。

决定：

## D-109｜最近查询必须整词去分类词，文章查找必须走标题通道（2026-10-29）

## D-112｜测试按当前契约对齐，不删除失败用例（2026-10-30）

`licensed_full_text` 已统一落 `reading_html`，发现结果新增 `dates/undatedUrls/allDatedBeforeCutoff` 字段；对应单元测试按当前 API 契约更新断言，断言正文格式而不是旧 `bodyText`。retention 的 2 项 `CONSOLE_STALE` 是真实保护链路问题，保留失败状态、不删除、不 skip；后续应继续缩小 `protection` 批量语句中触发 stale 的语句。

### D-112：已清理文档的保护快照跳过无载荷版本

- 决定：`snapshot()` 仅对 `input_hash IS NOT NULL` 的文档插入 `console_content_versions`；已被 `retention.purge` 清空正文的文档只推进 `version`，不写无法通过 `console_version_payload` 校验的快照。
- 理由：清理后 `input_hash` 为 NULL，快照触发器无法匹配；保护白名单本身应保留权限记录，但不该伪造可恢复载荷。
- 代价：清理后的保护记录没有新的可恢复正文快照，符合永久清理语义；正常文档不受影响。
- 验证：retention 7/7、全量 717/717；未删除测试。

### D-113：多主题长查询不绑定单一雷达分类

- 决定：长度 >400 字或顿号 ≥8 的校园查询视为多主题；不设 `radarCategory`，按发布时间列最新跨分类校园资讯，并明确提示可指定下一类。
- 理由：只要句中含「竞赛」就锁竞赛，会把“全部最新通知”答成竞赛专场；长句直接进 FTS 也会稀释召回。
- 代价：不在一轮内逐条覆盖所有主题；回答先给最新公开资讯，再让用户指定分类。
- 验证：真实 687 字符查询不再竞赛-only、无 500；全量 718/718。

### D-114：公共标题/来源检索改用 instr 子串匹配

- 决定：标题与来源检索使用 `instr(column, ?) > 0`，参数只做 300 字符上限，不再构造 `%...%`。
- 理由：D1 对超过约 50 字节的 LIKE 模式报 `LIKE or GLOB pattern too complex`，完整中文标题必然触发；`instr` 支持任意长度中文子串。
- 代价：无法利用 LIKE 前缀索引，但公开检索本来就走 FTS/子串，数据量可接受；后续若量级上升再迁 FTS。
- 验证：完整标题、前缀、`研究生`、`2026年研究生学业奖学金拟获奖名单公示` 均返回正确文章；`article-analysis-public` 4 项通过；全量 721/721。

### D-115：按句式决定检索词，而不是一律「最近 + 分类」

- 决定：祈使句（「找/帮我找/看看」）按对象检索；带「关于」的陈述句优先按文章标题查；疑问/宽泛列举（「有哪些/分别是什么」）不加「最近」，走分类列表；上一轮结果反馈（「只能找到这两条吗」）沿用上一轮话题，不新增地点/搜索词。
- 理由：固定「最近 + tag」会把「2026年研究生奖学金获奖情况」缩成最新两条，也会把结果反馈误判成地点请求。
- 代价：句式识别是启发式，需要真实回归集持续覆盖；不针对单个标题写分支。
- 验证：奖学金两轮回答分别 3/4 个来源且带人数、公示期、附件名；「只能找到这两条吗」不再触发地图；全量 721/721。

### D-116：名单类问题不再固定拒答

- 决定：删除 `needsRoster` 的「本鱼只负责广外」硬拒答；名单/获奖/公示类问题先查校园库，证据不足再外部补搜，回答必须列人数、公示期、附件名和缺失原因。
- 理由：广外官网确实有名单正文和附件，固定拒答会直接把可用信息挡掉；名单属于真实校园事实，不能只靠外部摘要。
- 代价：需要容忍附件名单未解析的情况，明确「姓名在附件」而不是编造姓名。
- 验证：研究生学业奖学金 5321 人、国家奖学金 134 人、学院公示均可回答；云山学者名单走外部补搜。

### D-117：关键词实体必搜与免检索边界

- 决定：带身份词（老师/教授/院长/是谁等）或 2–4 字裸人名/主题的消息，去掉「了解下/介绍下」等引导词后，以剩余关键词同时查校园知识与校园雷达事件；问候语、无关陈述句、纯地点问题和脏话不进入关键词检索。
- 理由：用户明确要求「无论问什么先抓关键词」；但把任意短句都当关键词会导致「一饭在哪」走文章检索、「今天天气不错」触发事件检索，反而破坏地点和闲聊体验。
- 代价：实体识别是启发式，裸人名限 2–4 字且排除地名/活动/学院等词；遇到复姓或长机构名需要后续评测补充，不针对单个姓名写死。
- 验证：`了解下王春业老师`/`王春业老师是谁` 返回院长身份、3 个来源和活动；`你好` 不检索；`今天天气不错` 不触发关键词检索；全量 724/724。

### D-118：会话历史不再按条数裁剪

- 决定：模型上下文取最近 40 条（`historySchema.max(40)`），服务端 `conversation_messages` 不按条数删除，前端不再 `slice(-20)`，`AssistantHistorySchema` 不再限制 20 条；会话整体仍按 48 小时 TTL 过期。
- 理由：原 `historySchema.max(12)` 在会话第 13 条消息起直接抛 `INVALID_ARGUMENT`，导致所有后续消息在模型/工具执行前失败；历史 40/80 条与前端 20 条又让用户看不到完整记录。
- 代价：长会话请求的 prompt token 增加，由 16000 字符预算和 40 条上限共同约束；数据库消息行随会话存续期增长，TTL 清理仍生效。
- 验证：复制的 34 条消息会话发送新消息返回 200，两个检索工具成功；历史接口返回全部 34 条；全量 724/724。

### D-119：正文优先与陈述式先答后搜

- 决定：陈述句不再被校园闸门直接拒绝；回答阶段先给通用/常识层面的直接回答，再按「整句→关键词」检索校园知识/雷达并用来源补充。文章查询只要正文可读且 URL 有效，就必须按正文回答，不可只回复「标题存在」或用单一来源限制把正文卡片过滤掉。
- 理由：用户明确要求「知道就知道，不知道就说不知道」，而旧链路把「没有精确标题证据」等同于「什么都不能说」；文章正文被相关性/单一来源规则二次过滤后，模型只能看到标题。
- 代价：陈述句有误检索成本，需要 `isContentStatement` 排除问候、天气、地点、最近/有哪些等；正文优先仍要求来源可读，不能用未授权摘要冒充正文。
- 验证：公报、地震补助通知、图书馆讲座三问均按正文回答；`学校有几个校区` 先答后补来源；全量 727/727。

### D-120：校区答案的尾部自我否定在表达层清理

模型在「学校有几个校区」类问题上会先给出正确事实，再追加「本轮资料只分别列出…」「是否还有其他校区，资料没有说明」等自我否定。这类句子不改变事实，但会让用户误以为答案不完整。

决定：在 `assistant-output.ts` 的表达清洗中按句子删除「不过/但本轮资料只…」「是否还有其他校区…」「本鱼只从本轮资料…」，并清理悬空逗号；不删除「北校/南校」等通用补充。引用、数字和正文事实不受影响。测试覆盖两种实际出现过的变体。
