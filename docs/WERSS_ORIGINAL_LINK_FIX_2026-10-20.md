# WeRSS 微信原文链接字符修复

日期：2026-10-20（Asia/Shanghai）。范围：用户本地 Docker `we-mp-rss`，8001 端口。

## 问题与定位

用户实际执行六公众号消息任务后入库六篇文章。其中四条 `url` 保留了微信读书 reviewId 内的 `~`，原文短链应还原为 `_`。用户样本：

- 修复前：`https://mp.weixin.qq.com/s/oi~Lh3K0LZ92f~LtQBSljQ`
- 修复后：`https://mp.weixin.qq.com/s/oi_Lh3K0LZ92f_LtQBSljQ`

实际 API 在修复前已返回错误 URL；前端文章弹窗将详情的 `url` 直接绑定到“查看原文”，定位到后端生成与持久化阶段。运行容器的 `core/wx/model/weread_mp.py` 错误地说明 `~` 必须原样保留，并按此拼链。本地下载包已经有字符还原，但运行容器没有该处理。

## 实施

1. `build_mp_url` 将微信读书文章 token 的 `~` 还原为 `_`。
2. `build_mp_link_from_review_id` 先移除准确的公众号前缀，再调用统一的短链构造函数。去除泛用的末尾 `_` 分割，保留 token 自身已有的下划线。
3. 更新当前容器运行文件，同时同步本地下载包中的两个链接构造函数；其他采集代码保持。没有改前端，也没有扩大为全站字符替换。
4. 通过 SQLite backup API 生成一致备份，再以一个事务仅更新四条 `articles.url`。每条都要求旧 URL 与该文章的微信读书 ID token 一致。文章 ID 继续保留微信读书编码，用于去重及正文请求。
5. 清理文章列表、详情的派生缓存，重启现有容器加载新代码。重启前主队列、正文队列均无当前或等待任务；没有重建容器或改变挂载、账号、密码、消息任务配置。

修复补丁：[weread_mp.patch](verification/werss-link-fix-2026-10-20/weread_mp.patch)。下载包对应文件：`CampusOS_Codex_完整设计文档_v2/we-mp-rss-main/we-mp-rss-main/core/wx/model/weread_mp.py`。

## 实际结果

- 修复事务完成时：6 篇文章仅四个 URL 改变，其他文章字段完全一致；81 个订阅、1 条消息任务、1 个用户的全部字段一致。
- 重启后实际列表 API：文章 6、订阅 81、消息任务 1，带 `~` 的原文 URL 为 0。样本的详情 API 也返回用户提供的正确地址。
- 现有自动正文补抓随后处理了修复链接的四篇文章：每篇 `has_content` 从 0 变为 1、`fix_fail_count` 从 2 变为 0，并写入正文与摘要。其余两篇文章保持。文章 ID、标题等标识未改变。
- 重启后与备份再次对比：81 个订阅、消息任务、用户的全部字段仍一致，包含原有密码哈希。没有修改登录凭据。
- 运行文件 SHA256 与保存的补丁后文件一致：`ee95f83444aa00a310496fd867c521e011ba854e70e6263ce1a8a651eaf116c5`。
