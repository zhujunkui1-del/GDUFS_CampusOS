## 工作流观察

- 周末活动通过 `search_campus_events` 日期索引检索。原来校区词也作为文章关键词，排除了只写楼宇地址的有效活动；现改由结构化 `campus` 过滤。
- 活动参与与可报名分开处理：普通「有什么活动可以参加」可列有日期的活动，并标明报名要求未知；明确「可报名」仍要求开放报名证据。`campus_notice` 不再混入可参加活动。
- Q10 的空结果此前因固定答复语气与校验冲突而整条被拦，现以索引未命中的实际状态回答，任务标为 `insufficient_evidence`。
- 最近食堂比较和地点分类查询使用 `spatial_read`，不依赖模型比较坐标。路线摘要从 `plan_route` 结构化距离和用时生成。

## 日历链接和 AI 复核

- 过期 `event` ID 携带有效 `article` ID 时，Preview 浏览器打开文章详情且没有失效告警；最终运行版本：`cfc88d26-3bcc-4869-ad5a-20238fb8989a`。
- Preview D1 读数：`calendar_ai_cap=200`、UTC 当日调用 `200`、`needs_enrichment=41`。队列中的条目会在下个 UTC 额度日继续（约北京时间次日 08:00）；本轮不能把额度耗尽后仍排队的条目说成已 AI 复核。
- AI 调用数包含文章活动提取及媒体 OCR。逐篇队列只接收有授权且可读取的正文；没有正文权限的文章不会发送到 AI。
- 单篇调用、证据引用、预算耗尽保留队列等有单元测试覆盖。
