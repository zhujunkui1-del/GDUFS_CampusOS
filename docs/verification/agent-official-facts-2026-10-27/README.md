# Agent 人物任职、名单范围及工具失败修复｜2026-10-27

负责人截图的症状是：短人名只答“已完成查询”；将云山工作室、科研项目等不同“首席专家”拼成南校名单；追问戴建业的身份时出现“工具参数无效”。实际回放又发现：上一句已引用聘任，下一句却因内部没有直接证据而否认；联网HTTP失败被写成没找到证据；模型出现空回复、截断、南北校混淆及学院错误归组。

当前人物身份问题能实际查询官方聘任报道和学院介绍，回答戴建业的正式云山工作室头衔，保留原文引用。没有取得权威的“南校独立人员名册”，不声称已补齐；有官网正文时仅展示来源原文资料，不再让模型拼接未经核实的校区/学院名单。旧聊天消息保留，重新提问使用新逻辑。

## 实现

- policy.ts按公开任职/名单问题选择官方来源，先执行原校园知识检索，再补官方联网核实；不因搜到任意正文就认为证据足够，也不调用小红书。
- official-search.ts读取学校公开站内搜索的tourist模式、全文范围3、首页10条、最多4结果/2篇正文。协议依据为官网公开搜索脚本；不登录学校系统、不追踪点击、不执行网页脚本。Exa失败或空结果时可回到官网检索；Exa正文获取失败可直接读白名单HTTPS静态HTML页，包括教师目录，所有读取有大小和时间界限。无法取得正文仍标search_excerpt/title_only，不冒充全文。
- intent.ts将没有明确内容意图、不是已知地点/地图命令的短主题作确定性澄清，不调用模型或地图工具。使用真实CampusMapService检查已知地点；其NOT_FOUND异常只在该匹配检查处转为未匹配，不吞权限或其他错误。
- 注册器向纠正阶段提供同一Zod契约的字段路径/原因，不回传输入值；Orchestrator保留一次执行前纠正、原权限/确认和Strict Schema。截图旧请求没有保存原始工具参数，因此没有断言它究竟哪个字段错误。
- model-run.ts识别空最终回复，同一证据最多重生成一次，工具不重复；仍空则明确失败。实测规划曾被单次1024截断，Preview受信配置改为最多2048，并按整轮实际剩余量裁剪；整轮4096输出token、6请求、250000总预算保持。普通HTTP用户不能改变这些配置，Production保持原配置。
- answer-scope.ts不从讲座举办地推出任职校区；无正文逐字依据的校区断言去除并标未知。校园人员名单没有可信校区投影时，仅引用官方正文资料，或说明未取得足以核实名单的正文，避免模型错误分组。个人身份回答不受名单格式影响。

保持原Agent、Registry、校园知识/雷达两Skills、五项地图Skills及Source Card样式；没有创建第二套Agent或人员数据库，不改13类文章taxonomy、发布状态、HTML/CDN、人工下架、门禁/白名单及私有隔离。外部资料只作临时问答证据，不自动进入D1公开文章；不部署Production、不新增付费服务或套餐。
