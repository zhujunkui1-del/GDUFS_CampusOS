# 小红书完整会话持久化与真实查询

## 核对与修复

此前Cookie文件从12:51一直存在：17条Cookie、固定设备标识一致、挂载路径正确，未发现文件丢失或加载失败。因此不能根据“文件还在”判断会话有效，也不能把旧接口未找到页面标记就直接归因为源站强制掉线。原适配只存扫码快照、每次新建浏览器，没有完整复用浏览器状态。

现改为专用Edge的launchPersistentContext，固定runtime/xiaohongshu-browser-profile。浏览器正常更新Cookie、LocalStorage等；重开同一目录，旧JSON仅首次迁移，之后不覆盖新状态。不读取日常浏览器资料，不模拟UA、不处理验证码、不进行发帖/评论/点赞或读取私信。会话目录不进入Git/D1/模型。

登录状态由真实页面用户状态判断。未加载/无法确认保留unknown/null；可见登录提示才标login_required。页面正文里的“安全验证”等文字不作为认证指令，避免把普通内容误当会话失效。

## 实际验证

- reopen.json：同一会话关闭前logged_in，关闭后重新打开仍logged_in；没有再次要求扫码。
- service-restart.json：正常关闭来源浏览器，重启两个Node程序，再打开同一目录仍logged_in。
- south-canteen.json：实际“广外南校一饭有什么好吃的”，约6.2秒返回2条真实笔记，均有正文。
- browser/live.json：真实Preview模型两回合“广外南校一饭有什么好吃的”→“调用小红书来查”通过；实际调用xiaohongshu_browser_local，两轮站内执行约6.9秒/3.5秒，均返回4条来源；正文摘录和原文链接可见。

其中《广外南校吃什么？三个饭堂一篇讲清楚》原文明确“一饭｜文采园”，列出鸭血粉丝汤、五谷渔粉等个人推荐；非校方结论，未承诺档口当前营业或菜品现行。真实URL、时间与有限摘录在回执，不伪造或替换平台内容。

另修正“调用小红书来查”这种短追问：继承本账号对话里的具体主题，跳过之前纯搜索指令。明确要求小红书会进入对应来源；奖学金截止等仍以官方为准。来源列表在回答有有效引用时只显示实际引用条目，保留原编号，不再把未引用的书单等候选铺给用户。机器证据保留。
