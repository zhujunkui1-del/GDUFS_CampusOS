# 建筑资料与留言附件验收｜2026-11-14

## 已发布功能

- 地图点选沿用原地点详情抽屉，显示简介及最多3张图片预览；“更多图片”进入抽屉内二级图库，提供返回和关闭。点击预览也可打开图库。
- `/admin/buildings` 提供建筑搜索、选择、简介修改、多图上传、上下调整顺序、移除和保存；109个可见地点可管理。简介先按已有名称、类别和区域编写，没有虚构开放时间、楼层、部门分布或沿革。
- 留言支持昵称选填、正文及多张图片；游客和登录用户均可提交。管理端“反馈”提供私密预览及下载，原倒序与待处理/已归档规则保持。前台无留言列表、附件列表或本人历史。

## 图片来源与导入

负责人本轮明确指示使用 `CampusOS_Codex_完整设计文档_v2/assets/source_maps/广外地图` 的建筑图片，优先“风景图”。本轮人工查看缩略图后，导入全部20张风景图及28张补充实景照片，48个唯一文件、51条建筑关联，覆盖24个建筑/地点（含组楼和单栋的共用照片）。清单见 [逐项来源、原图SHA256和目标路径](BUILDING_PHOTO_IMPORT_2026_11_14.json)。

只从照片名称与实景内容能够对应的建筑导入，不由照片推测GIS位置。粗略、卫星图及细节中的地图、航拍建模截图未加入公开图片；原图留在资料目录。输出保留画面和已有水印，按EXIF方向矫正、长边最多1600像素转WebP并移除元数据，48张合计7,843,582字节。正式资产位于 `public/buildings/`，不从外部图片站加载。

本项目展示依据为负责人本轮明确导入指示；不将这些图片标记为自由商用素材，也未推断额外的对外许可。原始网页URL、摄影者许可文书未在资料目录给出，来源清单如实记录本地原始文件，不捏造版权来源。新上传建筑图由有管理权限的负责人选择并保存后关联；用户留言图不自动进入公开图库或RAG。

其余地点没有能确认归属的实景照片，显示“暂无图片”，由后台后续添加；113个源地点的基础简介随代码提供，现有4个隐藏体育标签沿用原审核状态，不显示在管理选择中。

## 服务与访问边界

- 新增迁移0070：`building_profiles` 保存管理端覆盖资料，`project_images` 保存动态上传图片及用途/留言关联、文件名、MIME、时间。管理员资料更新与审计使用D1原子batch；留言与附件也原子写入，任意附件不合格时不产生半条留言。
- 初始照片为本地静态文件。动态图片使用已有D1，未新建R2、付费存储或更换架构。客户端将上传照片规范化为长边最多1600像素的WebP；服务端按JPEG/PNG/WebP签名验证，单文件1,900,000字节以内，为D1每行2,000,000字节平台限制留出元数据空间。依据：[D1限制](https://developers.cloudflare.com/d1/platform/limits/)。
- `GET /api/public/building?id=...` 只读公开建筑资料；`GET /api/public/building-image?id=...` 强制 `kind=building`，不会读取留言图片。
- `POST /api/public/feedback` 同时兼容原JSON和multipart；沿用同源校验，上传使用已有边缘限流绑定；不新增验证码、登录门槛、字数限制、额外解释段落或审批流程。
- `GET /api/admin/feedback-image?id=...` 强制Console管理员鉴权及 `kind=feedback`，`no-store`；加 `download=1` 返回附件下载。普通账号Cookie不能读取。下载名进行HTTP头编码，图片固定MIME并nosniff，不接收SVG。
- `GET/POST /api/admin/v2/buildings...` 继承Console会话、实时admin权限、写入同源/CSRF和会话请求限额。上传和资料更新进入原Console审计台账；日志不记录图片或留言正文。
