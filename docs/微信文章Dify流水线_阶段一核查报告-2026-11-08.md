### 2.2 HTML meta：这是最关键的发现

### 3.2 工作流全生命周期：✅ 闭环完整

这是本次核查最重要的正面结论。**导入 → 草稿运行 → 发布，三步全部实测跑通**：

| 步骤 | 端点 | 结果 |
|---|---|---|
| 导出当前配置 | `GET /console/api/apps/{id}/export?include_secret=false` | ✅ 200，YAML |
| 导入为新应用 | `POST /console/api/apps/imports`，**JSON body** `{"mode":"yaml-content","yaml_content":...}` | ✅ 200，返回新 `app_id` |
| 草稿运行 | `POST /console/api/apps/{id}/advanced-chat/workflows/draft/run` | ✅ 200，SSE 22 帧 |
| 发布 | `POST /console/api/apps/{id}/workflows/publish` | ✅ 200 `{"result":"success"}` |
| 删除 | `DELETE /console/api/apps/{id}` | ✅ 204 |

**两个反直觉的坑（已实测确认）**：

1. **`imports` 必须用 JSON body，不能用 multipart。** multipart 形式会返回 `422 missing field "mode"`，即使 mode 字段确实在 multipart 里。这与 Dify 官方文档示例不一致。
2. **导出再导入，`dataset_ids` 绑定会被保留。** 导出的 YAML 里 `dataset_ids` 是加密串（如 `/+g2vSNEzYwbOAZkKqMFZOr3rCy66l/...`），不是明文 UUID。但导入后通过 `GET /workflows/draft` 读回来，拿到的是**明文 UUID**，且与原来完全一致。这意味着**同一实例内做 DSL 快照/回滚是安全的**，不必手工重绑知识库。

### 3.3 ❌ Dify 没有版本管理 API

这是本项目最大的结构性缺口。实测不存在的端点：

- `GET/POST /workflows/history`、`/workflows/versions` → 405/404
- `POST /workflows/draft/restore`、`/workflows/publish/restore` → 404
- `GET /node-runs` → 404
- `PATCH /workflows/history`、`/workflows/versions` → `{"message":"No valid fields to update"}`

**推论**：第九节要求的「版本号 / DSL 快照 / 回滚」**不能由 Dify 提供**，必须由 CampusOS 侧自建。这恰好和 §3.2 的「导出→导入保留绑定」形成配合：我们自己存 DSL YAML 快照，回滚时用 `imports` + `publish` 重建。

### 3.4 知识库 API：Console + v1 双通道

**Console API（Cookie + CSRF）** ——管理面全量可用：

| 能力 | 端点 | 结果 |
|---|---|---|
| 列表/详情 | `GET /console/api/datasets`、`/datasets/{id}` | ✅ |
| 文档列表 | `GET /datasets/{id}/documents` | ✅ |
| Segment 列表 | `GET .../documents/{doc}/segments` | ✅ |
| 改 Segment 内容 | `PATCH .../segments/{seg}` | ✅ 200 |
| 删 Segment | `DELETE .../segments/{seg}` | ✅ 204 |
| **删文档** | `DELETE /datasets/{id}/documents/{doc}` | ✅ 204 |
| **建文档** | `POST /datasets/{id}/documents`（需先 `/files/upload`） | ✅ |
| 上传文件 | `POST /console/api/files/upload`（multipart，field=`file`） | ✅ |
| 检索测试 | `POST /datasets/{id}/hit-testing` | ✅ |

**v1 Dataset API（Bearer token）** ——更适合服务端同步：

| 能力 | 端点 | 结果 |
|---|---|---|
| **建文档（文本）** | `POST /v1/datasets/{ds}/document/create-by-text` | ✅ 200 |
| **建文档（文件）** | `POST /v1/datasets/{ds}/document/create-by-file`（multipart：field=`data` + field=`file`） | ✅ 200 |
| **更新文档** | `POST /v1/datasets/{ds}/documents/{doc}/update-by-text` | ✅ 200 |
| **删文档** | `DELETE /v1/datasets/{ds}/documents/{doc}` | ✅ 204 |
| 读文档/Segments | `GET .../documents/{doc}`、`.../segments` | ✅ |
| ~~索引状态~~ | `GET /v1/datasets/{ds}/indexing-status` | ❌ **404** |

**⚠️ v1 create-by-file 的坑**：用纯 JSON body + console file_id → `400 no_file_uploaded "Please upload your file."`。**必须 multipart**（field `data` JSON + field `file` 二进制）。

**⚠️ v1 files/upload with dataset key → 401**。上传文件只能用 Console API。

**⚠️ indexing-status 不存在**：无论是 batch 级还是文档级都返回 Flask HTML 404。这意味着「索引状态」只能靠轮询 `GET /documents/{doc}`，看它的 `indexing_status`、或直接看 dataset detail。

### 3.5 Dataset service key

```bash
POST /console/api/datasets/api-keys {"type":"dataset"}
→ {"token":"dataset-...","type":"dataset","dataset_ids":[]}
```

- `dataset_ids: []` = **对全部数据集可见**（含旧试点库）。这是「最小权限」的反面，生产环境应显式填入数据集 ID。
- token **只显示一次**，后续 GET `/console/api/datasets/api-keys` **不返回 token**（只返回 id/type/created_at）。丢了必须重建。

| `updateDocumentFromText(ds, doc, name, text)` | `POST /v1/datasets/{ds}/documents/{doc}/update-by-text` |
| `deleteDocument(ds, doc)` | `DELETE /v1/datasets/{ds}/documents/{doc}` |
| `getDocument(ds, doc)` | `GET /v1/datasets/{ds}/documents/{doc}` |
| `waitForIndexed(ds, doc, timeoutMs)` | 轮询 `getDocument`（因为 indexing-status 不存在） |

凭据：`DIFY_DATASET_API_KEY`（Server-only Secret），不使用 Console Cookie。

### 7.4 版本与回滚（绕开 Dify 无版本 API）

```
发布前：
  1. GET /console/api/apps/{app}/export?include_secret=false  → YAML
  2. INSERT INTO workflow_versions(app_id, version, dsl_yaml, status='published')
  3. POST /console/api/apps/imports  → 候选 app_id
  4. POST /console/api/apps/{candidate}/advanced-chat/workflows/draft/run
  5. 对比测试 → 人工审核
  6. POST /console/api/apps/{candidate}/workflows/publish
  7. 更新生产 app 的入口指向候选（或把候选 YAML 导入生产）

回滚：
  1. 取 workflow_versions 里上一个 status='published' 的 dsl_yaml
  2. POST /console/api/apps/imports → app_id
  3. POST /console/api/apps/{app_id}/workflows/publish
```

**关键约束**：同一实例内 DSL 导入导出会保留 `dataset_ids` 绑定（已实测），所以快照可以直接回放，无需手工重绑。
