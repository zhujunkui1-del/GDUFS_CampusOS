# S1 导航滚动灰框验收（2026-10-14）

## 触发条件与实际复现

负责人在392aa2f版本回验仍有灰框，并补充：导航面板装不下内容、出现垂直滚动条时触发。已连接负责人当前Edge配置，用临时地图标签页和608×440视口覆盖复现：地物被矩形底色覆盖，DOM标签仍显示；关闭面板恢复。测试没有读取个人GPS。

关键证据来自连接浏览器的可见标签页JPEG截图。之前Playwright/CDP截图未显示此异常，不能用其通过结果证明浏览器最终合成画面无异常。

## 实施

- `.route-planner`保留定位、白色背景、圆角、阴影和最大高度，使用非滚动外框。
- `.route-planner-scroll`负责内部滚动，保留滚动条、触摸/键盘操作和稳定的滚动槽。
- 标题与关闭按钮留在固定外框；内部滚动102px后，关闭按钮纵向位置不变。
- 不通过改底色掩盖异常；不新增持续重绘或定时器。

这是带圆角/背景/阴影的外框直接成为滚动容器时，在当前浏览器显示合成中出现的异常。对照确认了触发结构；未声称定位到Chromium引擎内部某行代码。

## 回归与证据

新增E2E检查外框不滚动、内部实际溢出且可滚动、关闭按钮稳定、关闭后清理。原生窗口矩阵改为滚动内部区域。类型、Lint、38单元通过；Next/OpenNext生产构建通过。生产版本浏览器结果在PROGRESS.md记录。

最终生产Chrome/Edge完整回归各47通过/5跳过。实际Edge生产显示截图最长背景行101px通过，初始化镜头与开发对照不同，不作逐像素比较。原生窗口覆盖与临时标签页已恢复/关闭，3000生产预览保留。
