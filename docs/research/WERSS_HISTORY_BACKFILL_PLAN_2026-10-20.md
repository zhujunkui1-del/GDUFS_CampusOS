# WeRSS：81 个公众号按日期补抓历史文章

日期：2026-10-20（Asia/Shanghai）。本轮是方案与只读能力核对，没有修改消息任务、采集器、授权或已有文章，没有启动历史批量任务。

用户已确认 81 号每日任务能取得每号最新一篇。当前运行的 `MpsWereadMP.get_Articles` 直接调用 `/api/mp/cover`，忽略历史分页参数，只能发现最新一篇；调整消息任务 Cron、最大页数或刷新结束页不能改变该路径的能力。

使用当前部署自己的授权，仅对既有学校公众号 `MP_WXS_3200207390` 读取一次 `/web/mp/articles` 第一页，返回 `WereadMPAPIError` / `-2012`。没有跟进翻页、写文章、创建任务或加书架。该结果表示当前凭据和请求方式没有取到历史列表，不能断言接口永久停用，也不能据此判断目标号没有历史文章。[实际结果](WERSS_HISTORY_LIST_CHECK_2026-10-20.json)。

## 上游实现与本地差异

当前上游 main 仍为 `d94db01372105bc479db81a0ac91829dac7f43e4`（2026-10-19 合并）。已通过 GitHub 连接器读取当前文件与提交元数据。上游存在 `_collect_via_article_list`，按 review group 数推进 offset；列表失败会回退到最新一篇。

上游默认增量算法在一页中遇到已有文章后会停止继续翻页，且有页数上限。现有各号最新文章已经入库，直接照搬该算法不能保证补齐 7 月以来的历史。因此应保留正常增量模式，并增加明确的日期补抓模式。

依据：[上游分页实现](https://github.com/rachelos/we-mp-rss/blob/d94db01372105bc479db81a0ac91829dac7f43e4/core/wx/model/weread_mp.py#L389-L489)、[主路径与回退](https://github.com/rachelos/we-mp-rss/blob/d94db01372105bc479db81a0ac91829dac7f43e4/core/wx/model/weread_mp.py#L492-L594)。

当前本地 cover 路径把 `time.time()` 写入 `create_time/update_time`，不能据此筛选真实原文发布日期。补抓前应取得目录或原文中真实发布时间，分别保存发布时间、发现时间和采集时间；无法识别原日期的条目保留待确认，不按采集时间算进目标范围。

## 建议实施顺序

### 1. 先跑通历史目录通道

- 先核对或刷新微信读书授权，使用同一既有账号读取一个公众号第一页。
- 只有能返回多个不同文章及可继续翻页的 cursor/offset，才认为目录能力可用。
- 若刷新授权后仍返回错误，先适配当前可用的历史列表通道；可采用有权访问的历史文章列表/导出清单作为输入，不能仅改页数或给错误响应改名后继续。
- 不因正文读取成功或 cover 返回成功就声称历史目录可用；不通过代理轮换、账号轮换或重试风暴处理限制。

### 2. 增加独立日期补抓模式

建议任务参数（这是待实施合约，当前 API 不支持）：

```json
{
  "mode": "backfill",
  "source_scope": "existing_81_feeds",
  "published_from": "2026-07-01T00:00:00+08:00",
  "published_to": "任务启动时固定的时间上界",
  "include_start": true,
  "skip_existing": true,
  "continue_after_existing": true,
  "fetch_content": true,
  "resume": true
}
```

- 默认将“7 月 1 日以后”解释为包含 7 月 1 日当日。
- 逐页发现标题、原链接、公众号标识、真实发布时间，再获取范围内正文；不为了筛日期先下载整个账号的全部正文。
- 已入库文章跳过重复写入，但不能作为历史扫描的停止条件。
- 仅在已核实目录排序、处理置顶/乱序等例外后，证明已覆盖日期边界或真实到尾页时结束。遇到一个旧日期条目不直接断言全部覆盖。
- 按公众号保存下一 cursor/offset、已确认日期范围、成功/重复/正文失败/日期待确认等状态；中断后从断点继续。
- 页数/请求数达到当前批次预算时标为“待续跑”，不能记为“历史全部完成”。

### 3. 单号小批次后再扩到 81 号

- 先选择一个有 7 月前后文章的账号，读取少量历史页，核对真实原链接与日期，再扩大该号日期范围。
- 通过后将相同任务用于其余账号，顺序或低并发、分批运行；已有每日任务通过稳定文章标识去重，不重置或删除现有数据。
- 授权/频控错误暂停并记录断点；等待正常恢复。目录失败不回退为 cover 后把历史任务标成功。
- 每个账号独立报告目标时间范围是否覆盖、正文是否仍缺失；缺失信息与无文章分开。

### 4. 后续再扩展为全历史

7 月以来目录和正文覆盖可核对后，复用同一任务并移除 `published_from`，按真实历史尾页逐批推进。不能预先承诺平台能够提供全部已删除或不可见文章。

每日维护也应使用列表增量，抓到上次已存边界之间的所有新文。当前“每日 cover 一篇”的机制在账号一天发多篇时可能漏掉中间篇，不是完整增量。
