# 07｜CampusOS 账号体系、游客模式与学校服务连接

## 1. 正式决定

**开发自有账号系统**：手机号验证码注册/登录、账号找回、可选密码、跨设备收藏/任务/会话/偏好；**保留无需登录的游客模式**。允许未来通过**一次广外统一身份正式授权**接入多项校内服务，而不是分别让学生向本系统提交数智广外/教务密码。

## 2. 登录方式与用户体验

- 游客进入 `/map`：公共地图、地点搜索、普通导航、公共知识/事件问答无需账号。
- 当用户尝试云端收藏、任务保存、长期会话、私人课表时，弹出轻量登录引导；当前地图路线和上下文在登录后保留。
- 手机短信验证码登录：不存在的手机号按产品规则完成注册；已存在的账号直接登录。
- 可选密码登录/设置（如正式实现），手机号找回使用验证码及安全校验；无效手机号或短信渠道故障不得造成死锁，应考虑备用恢复方式。
- 支持登出、删除账号与数据导出；个人资料仅收集必要字段。

## 3. 验证码与安全

- 验证码短有效期、单次使用、尝试次数/手机号/IP/设备限流；服务端只存验证码哈希或等效安全验证状态。
- 使用通过校验的短信平台（如腾讯云等），短信模板与适用地区要真实获批；短信服务可能产生实际费用，实施前通知负责人。
- 密码如实现，采用 Argon2id 或可靠密码哈希，不存明文；认证 Cookie 设置 `HttpOnly`、`Secure`、合适的 `SameSite` 并处理 CSRF。
- 高风险变更（换绑手机号、解绑校方身份、导出敏感数据）需要二次验证。
- 用户会话必须在服务端确认身份；API `userId` 不由浏览器自由传入。
- 支持账户禁用、会话撤销、登录设备列表/历史（注意控制存储个人信息最少化）。

## 4. 数据模型建议

- `users`：ID、昵称、头像引用、状态、创建时间。
- `auth_identities`：手机号（加密/受控）、密码哈希或认证方式标识。
- `login_sessions`：哈希会话令牌、过期、撤销时间、设备说明。
- `otp_challenges`：验证码挑战状态、次数、失效时间（短期清理）。
- `user_preferences`：地图、常去地点和关注领域。
- `user_memories`：用户允许保存的 Agent 记忆，支持查看、删除。
- `user_schedules`,`user_tasks`,`user_favorites`：业务数据按用户 ID 严格隔离。
- `external_connections`：学校身份提供者、已授权 scope、令牌状态、授权过期与解绑状态。
- `audit_events`：安全敏感操作记录，不存不必要个人对话明文。
- 新增 `user_model_configs` 与 `user_model_preferences` 的逻辑设计见 `12_MODEL_API_SETTINGS.md`；本次未生成或应用迁移。

## 5. 数智广外/教务系统绑定

**产品目标**：在个人中心设置“学校服务连接”，未来经学校统一身份认证（SSO）取得**明确针对 CampusOS 的第三方应用授权**后，连接课表、考试安排或本人查询成绩等服务。

**当前事实边界**：广外已有数智广外、教务系统和统一身份认证，但**并未核实存在对普通第三方开发者开放的读取数据接口**。即使学校主页可以扫码登录，也不等于允许 CampusOS 直接替用户自动抓取教务内容。

实现阶段：

1. P0：设计 `SchoolAuthProvider` / `AcademicDataAdapter` 接口以及账号中心的连接状态模块；不出现虚假的“已绑定”。
2. P1：完善课表用户主动导入、本人确认、私人云端存储；通过本人上传的文件实现个性化路线/日程。
3. P2：联系校方获取正式开发者授权、回调 URL、协议、数据接口、范围和数据处理要求。
4. 获授权后：使用标准化授权码/PKCE（如平台支持）获取仅限本人允许的数据；首次授权/范围扩大时明确展示；支持解绑、撤销和同步删除。
5. 成绩类数据额外最小化：仅在本人请求时读取，不进公共 RAG、不进入 Agent 长期通用记忆、不展示于他人页面。

**严格禁止**：代收学校密码、教务验证码/短信验证码、登录 Cookie；无权限模拟网页登录、绕过验证码、逆向或假造第三方 API；将学校账号和 CampusOS 账号混为一体。

## 6. 权限角色

| 权限 | 游客 | 登录学生 | 内容管理员 | 学校授权用户（附加） |
|---|---|---|---|---|
| 公共地图、问答、地点/活动 | 是 | 是 | 是 | 是 |
| 平台默认 DeepSeek / 临时自定义模型 | 是，临时配置不持久化 | 是 | 是 | 是 |
| 保存/测试/使用/删除持久模型配置 | 否 | 仅本人 | 仅本人，无代查权限 | 仅本人 |
| 云收藏、个人日程、长期记忆 | 否 | 仅本人 | 仅本人 | 仅本人 |
| 知识源采集审核、素材审批 | 否 | 否 | 是 | 取决于管理员角色 |
| 教务课表自动同步 | 否 | 尚无授权不允许 | 不允许代查他人 | 正式接口+本人 scope |
| 查询成绩 | 否 | 无官方接口不允许 | 禁止代查 | 需明确本人授权与实际接口 |

学校连接状态不自动授予管理员权限，管理员角色也不代表学校具有官方权力。

## 7. Agent 记忆和隐私

- 登录后历史会话可存储并跨设备读取；用户可以删除单条/整个会话。
- 长期偏好仅按用户允许保存，支持暂停与删除；不要自动把成绩/手机号记成偏好。
- 游客历史默认短期、匿名，隐私信息不应以公共 URL 暴露。
- 删除账号需要定义数据库、向量索引、R2 个人文件和会话记录的清除策略；涉及法定留存的审计记录单独管理并告知。

## 8. 需要验证与审批的事项

- 正式短信供应商及预算、实名认证/模板要求、地区可用性。
- 用户隐私政策、短信通知和个人数据保存期限。
- 学校 SSO / 接口是否授权、数据范围、回调流程与校方审核程序。
- 中国大陆访问 Cloudflare/短信/模型 API 的稳定性；必要时评估腾讯云部署，但不擅自切换收费资源。

## 9. 验收

验证码登录→登出→找回/换绑（如实现）→重新登录成功；游客可浏览公共数据；普通用户无法读他人会话/课表；管理员入口不对普通用户暴露；学校接口无授权时从未显示成功状态；账户删除后个人数据不再可访问。

## 10. 模型配置与身份切换

按负责人 2026-10-12 的澄清，游客可在当前页面临时使用自定义 API，不能保存配置或密钥；登录后才可保存多份本人配置和加密 Key。登录不会自动持久化游客输入，需用户明确保存。登出、换账号、撤销会话时清理敏感内存/缓存并阻止使用旧身份配置；删除账号级联清除模型配置与凭据。

配置读取、测试、使用、修改与删除均由服务端验证当前本人身份，当前模型选择与账号关联，管理员知识审核角色不能读取或代用他人的 Key。游客临时 API 不赋予私人 Skill 权限。完整生命周期、Secret、HTTPS、隔离和验收见 `12_MODEL_API_SETTINGS.md`。

## S3-A 运营身份边界（2026-10-17）

学生账号/SMS尚未落地时，Console采用独立运营身份和D1短期可撤销会话，不复用游客Cookie或信任客户端角色。公网Access JWT须签名/issuer/aud/期限/邮箱名单均通过；修改须同源+CSRF，并在数据库事务时确认会话仍有效。admin/operator/reviewer权限分开，不能因此访问学生对话、GPS、成绩或模型凭据。本地随机访问密钥仅允许loopback/local，不能向公网自动降级。

当前Cloudflare Access激活需要条款和超额扣费授权，未进行；公网管理API在可信认证配置前保持关闭。负责人首批管理员邮箱已收悉，认证选择待答复。此独立运营认证不代表学生账号系统完成，见D-041与docs/S3_A_CONSOLE_ACCEPTANCE.md。
