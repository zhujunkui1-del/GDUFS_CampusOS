# 01｜产品需求规格 Product Specification

## 1. 项目定义

- 名称：**广外通 CampusOS**。
- 愿景：从知道校园，到掌握校园；让 AI 不只回答问题，还帮助学生完成校园任务。
- 参赛方向：**（四）生活服务**。学生办事指引、校园反馈属于辅助的管理服务能力；不申报自由命题或社会服务。
- 平台形态：**一个响应式 Web 应用**，通过自己的 HTTPS 域名供电脑、手机浏览器访问；不开发独立 Android/iOS App。未来可考虑 PWA，但非当前交付前提。
- 开发方式：Codex 辅助实现自研 Agent/RAG/Skill/全栈业务；不强制使用 Dify。老师已说明可提交外部网站作为作品使用链接。
- 唯一地图范围：**广东外语外贸大学大学城校区**，必须包括**教学区、生活区和真实可通行的连接区域**，其中南校地下人行隧道是重点通行结构。
- 知识内容范围：广外全校的校级制度与政策可以检索，但涉及具体线下地点的地图定位只在大学城校区支持。

## 2. 核心问题

学生为了完成真实任务，需要在学校官网、学院网站、公众号、微信群、小程序、教务、地图、小红书间反复切换，并独立判断时效与可信度；校园地图虽有底图，但体育设施、宿舍楼栋、入口、跨区步行路径和校园信息经常缺失或难以联动。

CampusOS 提供：**找得到（空间）/ 查得清（证据）/ 安排好（计划）/ 做得成（技能执行）**。

## 3. 人群与权限

- 游客：可浏览地图、地点详情、官方/公共校园知识、公共活动、普通导航、非个性化 AI 提问。
- CampusOS 登录用户：在游客能力基础上保存收藏、任务、课表、会话和用户自愿保存的长期偏好，并支持手机号找回账号。
- 内容管理员：管理知识源、内容审核、素材审批与事件关联；不代表学校官方身份。
- 学校授权用户（后期）：如学校正式提供接入方式，在本人明确授权后按范围读取相关数据；普通账号不自动获得学校学籍或成绩数据。

## 4. 功能模块与优先级

| ID | 名称 | 必须交付的业务结果 | 优先级 |
|---|---|---|---|
| M01 | 校园地图 | 真实建筑/道路、两区覆盖、2D/2.5D、地点搜索与点击详情、跨区导航 | P0 |
| M02 | AI 校园助理 | 自然语言→总控 Agent→Skill 调用→真实地图/卡片动作 | P0 |
| M03 | RAG 校园知识 | 已核实官网自动索引、来源链接、时间与适用范围、异常处理 | P0 |
| M04 | 多站校园任务规划 | 地点与时间约束、真实路径算法、结果时间线、用户调整重算 | P0→P1 |
| M05 | 个人课表与学业服务 | 官方办事入口、登录后个人课表/任务录入、导入与关联；官方数据同步后期 | P1/P2 |
| M06 | CampusRadar 校园雷达 | 校园公告与活动结构化、截止时间、可核验的地图地点 | P0→P1 |
| M07 | 实景与智能导览 | 有授权的建筑照片、室内图片、第三方全景原文链接/许可嵌入 | P1 |
| M08 | 办事与校园反馈 | 跳转学校现有官方反馈/报修/教务渠道，部门及辅导员指引 | P0→P1 |
| M09 | Campus Moments | 地点动态、限时消息、求助、位置社交，明确 P2 不阻塞初赛 | P2 |

### M01 校园地图硬约束

1. 实际地图覆盖教学区、生活区、两区之间的步行连接；不得只做一个区域。
2. 对建筑、体育馆、游泳池、露天足球/篮球/排球/网球场、宿舍片区与逐栋编号建立分级标签。没有核验的名称或位置不得猜测。
3. 路线使用真实可行的校内步行网络；考虑南校隧道地下路段、两侧入口与路网衔接；高德等官方步行规划可作为合规对照。
4. 点击建筑打开统一详情，提供去这里、收藏、问 AI、图片实景、相关活动及来源等能力（仅展示有数据内容）。
5. 地图使用官方地图开放 SDK；第三方地图图片需要负责人单独批准且具备使用许可。

### M02/M04 可验收的核心故事

用户："下午两点上课，先去打印、取快递再吃饭，帮我安排。"

- Agent 查缺失项：上课地点、出发位置、可用时间以及必要的停留时长；能够询问用户。
- `search_places` 返回真实地点；`plan_multi_stop_route` 调用真实道路算法并处理时间窗；`control_map` 返回受控地图指令；用户能够在地图上检查、修改任务顺序并重算。
- 无法满足所有时间条件时解释具体冲突；不虚构营业时间与道路。

### M03/M06 可验收的核心故事

用户："近期有什么适合计算机专业学生的比赛？在哪里办、什么时候截止？"

- 从官方来源和已审核非官方来源取得候选；识别发布时间/活动开始/截止时间；根据学年和校区过滤；只把匹配到实际大学城地点的事件投射到地图。
- 原始文章链接和可信度/适用状态可查看；非官方文章只能呈现为经验或线索。

### M05 个人化

采用 CampusOS 自有账号。支持手机号验证、账号恢复、登录后云同步个人收藏/日程/任务/偏好。课表可由学生主动录入或导入文件，经本人核对后使用。数智广外、教务连接入口属于 P2 待授权能力，**不得假装真实绑定**。成绩等信息只允许按本人明确请求查询，不进入公开向量库。

### M08 管理服务边界

CampusOS 不创建学校维修工单后台、不冒用学校审批、管理人员权限。提供经核实的官方流程、链接和线下办事位置；必要时建议联系相关部门或辅导员。

### M09 社交边界

作为扩展单独开发；默认不在初赛 P0 界面暴露不可用的社交功能。社区发言不能自动作为校园事实进入公共 RAG。

## 5. 当前不做 / 明确非目标

- 白云山校区地图、多校跨域导航。
- 全校园高精度可自由行走的 3D 游戏式数字孪生。
- 没有获准的第三方街景抓取、瓦片下载、POI 批量数据复制。
- 凭猜测生成完整室内楼层图、室内实时定位、人流密度实时预测。
- 用户未经授权批量读取私人微信群或教务/数智广外账号。
- 未取得学校 SSO 接口就上线读取成绩/课表的“绑定成功”。
- 直接开放无限制附近的人精准实时跟踪。

## 6. 产品信息可信度原则

- 优先使用新近、有效且适用的广外官方通知；非官方内容仅供参考，并保留原始链接。
- 明确区分 `published_at`、`fetched_at`、`verified_at` 与 `valid_until`；不可将“今天采集”写成“今天发布”。
- 官方自动入库依然需要来源白名单和内容校验；活动结构化地点、时间不完整则不自动生成地图标记。
- 用户提供的群聊要有适当授权，入库前脱敏、蒸馏、审核；不要公布个人原始聊天记录。

## 7. 体验原则

- 视觉：广外校园蓝白、Apple 式克制设计；精致 2.5D 地图优先，2D 辅助导航。
- 桌面端：左导航 + 中心地图 + 右侧可关闭 AI 面板。
- 手机端：全屏地图 + 顶部搜索 + 底部抽屉 AI + 五项底部导航。
- 无阻塞登录：公共功能游客可用，真正需要持久化时再引导登录。
- 正式产品：不添加无意义“仅供演示”等标签；未核验/不可用/未授权事实必须诚实显示。

## 8. 非功能要求（初始质量目标）

- 地图常规交互目标：桌面设备接近 60 FPS，主流手机尽量不低于 30 FPS；真实值通过设备测试记录，不作为未经测试的事实承诺。
- 移动端触控适配：所有关键操作无需鼠标 Hover 即可完成。
- 账号和私人数据：服务端校验权限、限流、记录授权、可导出删除；不将用户成绩等敏感信息自动注入模型上下文。
- API/Agent：工具执行有超时/重试/错误状态；无法回答时给出可核实资料而不是伪造结论。
- 部署：提供可公开访问 HTTPS 链接、环境变量模板、真实依赖配置、部署说明、清晰测试结果。

## 9. 验收总则

每个功能必须经过：真实数据源核验 → 真实接口调用 → UI 行为验证 → 权限与出错测试。"文件存在/界面好看/模型说做了"不构成完成。项目总体验收按 `09_DEVELOPMENT_PLAN.md` 执行。
