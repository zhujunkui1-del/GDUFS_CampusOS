## 3. 模型配置与状态

配置包含：模型供应商、显示名称、模型名称/ID、API Key、按供应商规则显示的 API Base URL、启用状态、能力测试结果与最后测试时间。

供应商由服务端维护的 `ProviderRegistry` 定义：供应商 ID、协议适配器、允许端点、Base URL 是否可编辑、模型输入/列表支持、生成/工具/JSON 测试策略、限额与错误映射。前端下拉框由该注册表的公开元数据生成，不能自行增加未知供应商或开放任意 URL。

- 模型名称允许输入精确 ID；供应商有可用模型列表接口时，可由服务端获取供选择。列表出现不证明该 Key 有使用权限，最终以真实生成测试为准。
- 新增/修改配置可保存为未验证或停用状态；**通过所需能力测试后才能启用为 CampusOS Agent 的当前模型**。测试失败不删除用户输入和已有会话。
- 状态至少区分：`untested`、`testing`、`ready`、`failed`、`stale`、`disabled`。供应商、模型、端点、Key 替换或测试策略变更后使旧结果失效；显示名称修改无需重新调用供应商。
- 测试状态和能力由服务端生成，客户端传入 `ready`、`capabilities` 或 `user_id` 都不能产生权限或通过测试。
- “停用”保留登录用户的加密配置但禁止新调用；“删除”同步删除配置和凭据。两者都不能暗中启用默认模型。
- 启用、停用、切换、删除必须处理并发版本冲突。删除/停用当前配置后进入“请选择模型”状态；可在同一确认操作中由用户明确选择默认模型或另一配置，后续发送才调用选中的模型。

## 5. 密钥生命周期与身份隔离

### 5.1 游客临时 API

1. Key 与临时配置只保留在当前标签页的内存中；不写 LocalStorage、SessionStorage、IndexedDB、Cookie、Service Worker 缓存、数据库、KV、R2、Durable Object 持久存储或会话消息。
2. 通过同源 **HTTPS POST** 将临时凭据交给 CampusOS 服务端。供应商请求只由服务端发起；浏览器不直接访问供应商。Key 不放 URL、查询参数、路由状态或 SSE 事件。
3. 服务端在单次请求/AgentRun 内存范围内使用 Key，不依赖 Workers 实例全局变量缓存凭据，不把 Key 发往后台队列、长期任务或监控。
4. 跨页面导航可保持同一应用实例的内存状态；刷新、关闭标签页、切换身份、主动清除或到期后释放引用。临时有效期由服务端策略控制，建议初始最长 30 分钟，不能仅靠前端计时保障。
5. 用服务端签名的短期测试凭证绑定匿名会话、供应商、模型、规范端点、凭据的服务端 HMAC、能力与截止时间。凭证不含 Key；每次调用重新校验所提交 Key 和元数据，防止测试通过后替换目标、伪造能力或跨会话借用凭证。
6. 凭据失效时保留会话与真实工具状态，暂停生成并提示重新输入/测试或明确切换模型。不自动续期，不自动扣用平台模型额度。刷新后可保留非敏感的“会话此前使用自定义模型”标记以提示重新配置，但不得据此恢复 Key 或配置。
7. 游客登录后不自动保存临时 Key；用户明确选择保存，才执行经登录会话鉴权的加密持久写入。登录/登出/换账号时清理旧临时凭据与测试凭证。

内存清理减少暴露时间，不宣称 JavaScript 字符串可以被保证物理擦除。页面第三方脚本、分析 SDK、错误采集和状态调试工具不得读取、记录或持久化该输入。游客仍只有公共 Skill 权限。

### 5.2 登录用户持久密钥

- 保存/替换只能由服务端已验证的本人账号执行，Cookie 会话使用现有安全规则并验证 Origin/CSRF。客户端传递的所有者字段无效。
- 采用 **AES-256-GCM 认证加密**，使用 Workers Web Crypto 等经过维护的实现；封装和参数须经过安全审查与测试，不能自造加密算法。仅选择算法并不代表安全审查已经完成。
- 256 位随机主密钥保存在 Cloudflare Secret，按版本管理；主密钥不在 D1、配置文件、源码、前端或 Git 中。Secret 缺失/格式错误/解密认证失败时拒绝操作，不能退回明文储存。
- 每次加密使用独立的 96 位随机 IV，并落实同一主密钥下 IV 不重复的约束；认证标签为 128 位。加密封装记录格式版本、密文、IV、认证标签和主密钥版本，AAD 绑定 `user_id`、配置 ID、供应商、格式/密钥版本。篡改或把密文复制给另一用户应解密失败。
- 解密仅在受信任的服务端、本人授权已确认且目标端点已通过策略校验后进行；只用于供应商认证，不进入提示词、工具参数、对话、前端响应或审计内容。
- 新主密钥用于新写入，旧版本仅供受控读取/重加密迁移；轮换完成并核验备份恢复策略后才能移除旧 Secret。不同环境不共享主密钥。
- 替换 Key 原子更新凭据版本并使旧测试结果失效；删除配置事务内删除对应密文/IV/标签，账号删除同步清除其所有配置与凭据。备份的保存期限与到期清理单独记录，不能把逻辑删除宣称为即时清除全部历史备份。

### 5.3 共同保护

传输全过程为 HTTPS（浏览器→CampusOS→供应商）；含 Key 的 HTTP 请求直接拒绝，不能先接收秘密再重定向。当前 `http://127.0.0.1:8787` 开发预览只能用 Mock 凭据；真实凭据需使用受控 HTTPS 环境验证。

请求体、Authorization、Key 字段、供应商原始错误体、密文及测试凭证不进入日志、异常、监控或响应。日志只记录白名单的请求 ID、脱敏主体标识、供应商、模型、结果码、耗时与用量；错误由服务端映射后返回。凭据接口响应设置 `Cache-Control: no-store`，不被代理或前端持久缓存。第三方 SDK 的自动日志、遥测和异常输出必须一并审查。

## 6. Base URL 与出站网络策略

**首批仅开放经过审核的预设供应商端点。** 供应商允许自定义地址时，字段也只能选择或输入服务端审核登记的精确端点；不开放“任意 OpenAI 兼容 URL”。注册协议和供应商列表扩展需核验文档、服务归属、条款、隐私与运行时网络控制。

- 服务端解析、规范化 URL；严格匹配 `https`、精确主机、允许端口（首批 443）及供应商路径前缀/完整模板。禁用用户名/密码片段、查询/fragment、用户指定请求头和任意路径；模型 ID 不得拼接成不受控 URL。
- 使用服务端注册表构造最终请求地址；不能做模糊后缀匹配。拒绝 `localhost`、IP 字面量、伪装编码、内网、环回、链路本地、云元数据及 IPv4/IPv6 特殊地址；不通过拼接 `/chat/completions` 自动修复不可信 URL。
- 禁止自动跟随重定向；3xx 返回端点错误，不把 Authorization 转发到新主机。所有重试继续使用相同的已审核目标策略。
- 域名白名单本身不能保证防止 DNS 重绑定。将来开放用户控制端点前，必须校验全部 A/AAAA/CNAME 解析结果并让实际连接绑定到已校验地址，同时保持 TLS 主机名、SNI 和证书校验；设置独立受限出站策略并禁止访问内网/元数据服务。
- 如果当前 Workers 请求层不能可靠实现连接时目标约束，就保持官方预设地址模式，禁用用户控制端点；不能将一次 DNS 查询或正则校验当成安全保证。审核官方地址的 DNS/归属变化，发生异常暂停适配器。
- 限制请求/响应体大小、并发、超时与可调用路径；只允许模型协议所需请求。连接测试、模型列表、真实生成共用网络策略。

此策略用于防止 SSRF、DNS 重绑定、恶意重定向及凭据外送，不把网页上的供应商名称当成可信端点证明。

## 7. 服务端连接测试

测试不是只 ping URL、列模型或检查 Key 格式。流程为：

1. 验证会话、额度与供应商端点策略；不合规地址在发起任何网络请求前拒绝。
2. 用 Key 请求供应商，验证认证、目标模型存在且账号具有使用权限。
3. 发起限定输出量的最小生成请求，验证有效生成结果及终止状态。
4. 在独立测试环境请求一个无业务副作用的诊断工具，验证工具名称、调用 ID、参数 Schema、结果回传及后续生成。诊断工具不注册进正式 16 项 Skill，不读私人数据、不写日程或操作地图。
5. 当该适配器/Agent 工作流需要结构化 JSON 时，额外生成并在服务端验证 JSON 和业务 Schema。区分 `json_object` 与严格 JSON Schema 能力；跳过项记为 `not_required`，不能显示“已支持”。
6. 返回分项 `passed/failed/not_required/not_tested`、脱敏原因、耗时、测试时间和策略版本。只有必要项目全部通过才标记 `ready`，并签发绑定配置版本的测试结果/短期凭证。

测试超时、配额与并发全部由服务端强制，页面防重复点击只负责体验。建议初始总时限 20 秒、最多 3 次上游请求、同时每主体 1 个测试、每主体每分钟至多 3 次、每小时至多 20 次，并设 IP 与站点总预算；上线前按供应商限制调整并记录。每次输出上限、推理预算和费用边界按适配器配置，不能因为输出文本短就认定推理成本低。工具/JSON 检查不能在调用预算外无限补测；必要项目未完成时结果不通过。测试不自动重试，不测试真实个人业务写入。

游客测试依赖服务端签发的匿名会话、会话/IP 联合限流与站点总限制；不能允许伪造匿名 ID 绕过预算。登录用户测试本人已保存配置时只提交配置 ID，由服务端鉴权后解密；测试新 Key 只暂时使用，除非用户另行保存，否则不写库。

### 7.1 统一错误分类

| 错误码 | 用户说明 | 处理 |
|---|---|---|
| `MODEL_KEY_INVALID` | API Key 无效或已失效 | 检查/替换 Key 后测试 |
| `MODEL_NOT_FOUND_OR_FORBIDDEN` | 模型不存在或当前账号没有权限 | 核对模型 ID 与供应商权限 |
| `MODEL_ENDPOINT_INVALID` | API 地址不符合供应商规范 | 使用允许的端点；含 SSRF/重定向拒绝 |
| `MODEL_NETWORK_ERROR` | 无法连接模型服务 | 保留配置，检查网络后重试 |
| `MODEL_QUOTA_EXHAUSTED` | 供应商余额或额度不足 | 在供应商处理额度，或主动切换 |
| `MODEL_RATE_LIMITED` | 请求过于频繁 | 显示可安全采信的重试时间 |
| `MODEL_TOOLS_UNSUPPORTED` | 模型未通过 CampusOS 工具调用验证 | 不能启用该模型执行 Agent Skill |
| `MODEL_SERVICE_UNAVAILABLE` | 供应商暂时不可用 | 稍后重新测试/主动切换 |
| `MODEL_TIMEOUT` | 模型连接测试或生成超时 | 保留会话，提供重试入口 |
| `MODEL_JSON_UNSUPPORTED` | 未通过当前任务要求的 JSON 输出验证 | 阻止要求该能力的工作流 |
| `MODEL_TEST_BUDGET_EXCEEDED` | 已达到测试次数/调用预算 | 显示冷却或额度提示 |
| `MODEL_TEST_REQUIRED` | 配置已变化、未测试或测试已过期 | 重新测试后启用 |
| `MODEL_SELECTION_REQUIRED` | 当前模型被停用/删除或临时配置失效 | 用户重新选择模型 |

各供应商状态码/错误码须由适配器映射，不能把所有 401/403/429 机械解释为同一种原因。不能确定时显示已知情况和请求 ID，保留脱敏诊断；不回传上游原始正文或编造确定原因。

## 8. Agent、Skill 与失败恢复

模型选择层在现有 Orchestrator 之前解析服务端身份、平台/自定义模式、所有权、配置版本、能力与预算。模型选择不由提示词或用户传入的任意 config ID 决定。

- 每个 `AgentRun` 开始时固定本次模型来源、版本和能力快照；流式 UI 显示实际使用的模型，运行记录只存非敏感来源元数据，不存 Key。
- 切换模型影响下一个请求。正在运行时提示等待/取消；删除、停用或替换所用凭据必须协调取消相关运行并记录已完成工具，确认完成后不再用旧 Key 发起请求。已发送的上游请求不能被承诺即时撤回。
- 工具调用仍经过原 16 Skill 的注册表、Schema、AuthZ、确认与输出验证，模型不能新增权限。只有通过工具兼容测试的配置才能进入工具执行循环；自由文本“调用成功”不能触发 Skill 或 MapAction。
- API 错误时返回可理解的错误、重新测试和“切换模型”入口，保留已有消息、地图、路线、引用及工具执行状态。**未经用户明确选择和确认，不自动切换到平台模型，不用平台 Key 重试自定义失败请求。** 平台额度耗尽也不自动改用用户自定义 Key。
- 重试和切换后继续任务时，读取工具执行台账。写入确认令牌绑定本人、动作、参数和版本，副作用使用业务动作幂等键；已成功写入复用真实结果，处理中/状态未知先核对数据库，不重新创建任务。新增写入仍须原权限与确认流程。
- 地点搜索、路线算法、RAG 检索、MapAdapter、MapAction 与个人数据由原业务服务提供，模型切换不修改它们的 Schema、数据源、校园范围或权限。
- 公共 Embedding、索引构建、事件提取和后台知识采集使用独立平台服务配置；用户的对话模型不能改变向量维度或隐式重建公共索引，不把用户 Key 借给后台任务。
- 选择自定义供应商并不允许把整份私人档案发送过去；仅发送完成当次任务必需且本人允许的上下文。外部 RAG 文本继续作为不可信数据处理。

## 9. 数据库逻辑设计与迁移约束

沿用现有 D1/SQLite 的用户外键、UTC 时间、`*_json` 命名及版本控制。以下是待实现的逻辑结构，不是已经生成/应用的 SQL 迁移。

### 9.1 `user_model_configs`：本人配置与加密凭据

| 字段 | 约束/用途 |
|---|---|
| `id` | 稳定配置 ID，服务端生成 |
| `user_id` | 非空，外键 `users.id`，账号删除级联删除 |
| `provider` | 服务端注册的供应商 ID |
| `display_name` | 用户可读名称，长度受限 |
| `model_id` | 精确模型 ID，按适配器校验 |
| `base_url` | 服务端规范化的允许地址，不包含 Key/查询参数 |
| `encrypted_api_key` | 非空密文 BLOB，仅服务端使用 |
| `key_iv` / `key_tag` | AES-GCM 的 IV/认证标签；也可纳入有版本的封装 BLOB |
| `key_version` / `encryption_version` | Cloudflare Secret 主密钥版本/加密封装版本 |
| `credential_version` / `version` | Key 替换与配置并发版本 |
| `is_enabled` | 是否允许选择使用，布尔约束；停用不等于删除 |
| `capabilities_json` | 服务端实测能力、分项结果、策略版本和有效期，JSON 约束 |
| `test_status` / `last_tested_at` | 验证状态与 UTC 测试时间 |
| `created_at` / `updated_at` | UTC 创建/更新时间 |

建立 `(user_id, id)` 唯一约束供所有者关联校验，并对本人列表建立索引。密文字段不出现在对外 DTO 或普通查询投影中。用户导出配置也不包含密文或明文 Key。

### 9.2 `user_model_preferences`：当前模型选择

每个用户一行：`user_id`（主键/用户外键）、`mode`（`platform/custom`）、`active_config_id`（可空）、`version`、`updated_at`。

`platform` 时配置 ID 为空；`custom` 时 ID 可指向本人启用且测试有效的配置，或为空表示停用/删除后“待选择”。以 `(user_id, active_config_id)` 复合外键/等效数据库约束保证不能指向他人的配置。切换时事务校验所有权、状态、能力及版本。**当前使用状态由此表唯一决定，对外可派生 `is_active`，不另存多行可冲突的 `is_active` 标志。**

删除当前配置须在同一事务中清空引用、保持待选择状态并删除凭据；只有用户明确选择平台时才变更为 `platform`。匿名临时配置不写入这两张表，不给游客创建假 `user_id`。

迁移采用新增表和必要的非敏感运行来源字段，兼容现有 `users`、`login_sessions`、`conversations`、`agent_runs` 及业务数据；不重建账号、不覆盖日程/收藏、不给历史账号自动导入私人 Key。既有账号初始化使用平台模式。迁移须验证外键、跨用户约束、回滚/备份恢复及账号级联删除；生产启用前做好备份和环境隔离。

## 10. 服务端 API 设计

沿用 `08_DATABASE_API.md` 的 `ApiResult`、requestId、错误映射和会话边界。以下为待实现接口，不代表当前路由可用。

| Method | Endpoint | 权限/用途 |
|---|---|---|
| `GET` | `/api/model-providers` | 游客/登录；只返回审核供应商、公开模型/端点规则和默认模型状态 |
| `POST` | `/api/model-connections/test` | 服务端匿名或登录会话+限流；测试临时/未保存配置，Key 只在请求体中暂时使用 |
| `GET/POST` | `/api/me/model-configs` | 登录本人；获取不含秘密的配置列表/加密保存配置 |
| `PATCH/DELETE` | `/api/me/model-configs/:id` | 登录本人；修改、替换 Key、启停/删除配置及凭据 |
| `POST` | `/api/me/model-configs/:id/test` | 登录本人；服务端解密本人 Key 后真实测试 |
| `GET/PUT` | `/api/me/model-preference` | 登录本人；读取/切换平台或本人配置，校验并发版本与能力 |
| `POST` | `/api/agent/chat` | 原接口扩展；按经过校验的模型选择执行，不直接转发供应商输入 |

游客聊天携带临时配置、Key 及短期测试凭证，服务端验证后在该 Run 内使用，所有这些秘密均排除在消息持久化结构之外。登录用户使用已保存配置只传无秘密的选择信息，服务端按本人偏好及配置读取；拒绝跨用户配置 ID。模型选择不会从请求体中的供应商 URL 直接建立客户端。

配置响应白名单可包含 `id,provider,display_name,model_id,base_url,has_api_key,is_enabled,is_active,capabilities,test_status,last_tested_at,version`；永远排除 `api_key,encrypted_api_key,key_iv,key_tag`。找不到或非本人 ID 返回一致的不可访问结果，避免通过错误透露别人的配置存在性。管理员内容权限不允许代用他人的 Key。

持久写入/切换/删除支持并发版本与幂等；测试限制重复请求，不在网络失败后自动再次付费。平台默认模型的探测是受控运维任务，公开状态接口不在每次请求时触发平台付费生成。

## 13. 技术依据与核验边界

2026-10-12 查阅官方/原始技术资料，仅用于设计核验，未调用供应商或创建云端资源：

- DeepSeek 官方提供 API、工具调用和 JSON 输出文档；具体模型权限及 CampusOS 能力仍需真实测试，JSON 输出不能直接视为严格 Schema 保证。来源：[API 入口](https://api-docs.deepseek.com/)、[Tool Calls](https://api-docs.deepseek.com/guides/tool_calls/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

- SSRF 防护要求目标白名单、重定向控制及连接时地址约束；一次域名/地址检查不等于防住重绑定。来源：[OWASP SSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。
